## 1. 项目概述

### 1.1 项目名称

**本机项目助手（Project Assistant）**

### 1.2 项目定位

本项目是一款以本机项目管理、开发协作和 AI 辅助编程为核心的桌面助手。产品通过统一的项目入口，将近期使用过的项目、Codex 开发工作流、Git 信息、网络搜索和文件操作集中到一个界面中，降低开发过程中的上下文切换成本。

产品采用“本地优先、安全可控、逐步扩展”的建设原则：首阶段聚焦桌面端核心闭环；在桌面端稳定后，再扩展到安卓端、跨设备同步和远程控制。

### 1.3 产品愿景

让用户能够从一个入口完成以下工作：

1. 快速找到并打开正在开发的项目；
2. 在明确的项目上下文中向 Codex 提出开发任务；
3. 实时查看执行进度、审批请求和文件修改结果；
4. 通过 Git、搜索和项目工具完成验证与复盘；
5. 在保证安全和用户控制权的前提下，逐步实现跨设备协作。

### 1.4 核心价值

- **降低项目查找成本**：自动整理近期使用过的项目，并提供名称、路径和信息搜索。
- **统一 AI 开发入口**：让用户在选定项目后直接发起 Codex 任务，减少重复配置。
- **随时输入任务**：通过置顶悬浮球展开对话面板，让用户在其他普通桌面窗口中工作时无需切换到主窗口即可输入。
- **提升过程可见性**：展示任务状态、执行日志、审批节点和差异结果。
- **减轻工作记录负担**：自动感知项目内的工作活动，持续整理可追溯的工作树，减少手动记日志和整理上下文。
- **按含义找到文件**：支持用自然语言描述意图或内容查找文件，无需记住准确文件名或关键词。
- **强化操作安全**：对写文件、执行命令、Git 变更和远程操作保留确认与审计能力。
- **保持可扩展性**：将文件系统、Git、Codex、搜索和同步能力拆分为独立模块。

## 2. 项目目标与范围

### 2.1 首版目标

首版应完成一个可验证、可重复使用的桌面端核心闭环：

1. 用户启动应用；
2. 应用展示近期使用过的项目；
3. 用户按名称或路径搜索项目；
4. 用户选择项目并打开项目目录或指定文件；
5. 用户选择服务源、AI 模型和思考强度，在主窗口或常驻悬浮输入面板中提交任务；
6. Codex 在选定项目工作目录中执行任务；
7. 应用展示回复、执行进度、审批请求、错误和修改差异；
8. 用户可通过系统文件管理器查看修改后的项目。

Git 状态和网络搜索作为首版的重要配套功能接入，但不应阻塞上述核心闭环。

### 2.2 首版范围（In Scope）

- 桌面端应用基础框架；
- 近期项目记录、项目列表和模糊搜索；
- 项目目录、文件和 URL 的系统打开能力；
- Codex 会话创建、消息发送、事件接收和结果展示；
- 面向普通桌面窗口的全局常驻对话入口，支持悬浮球展开输入、全局快捷键唤起、任务状态反馈和收起/关闭；
- 桌面端 AI 模型、思考强度和官方源/中转站切换；
- 用户手动管理 cc-switch；应用自管中转站 profile 和 Key、连接测试与失败恢复；
- 文件修改差异查看；
- 必要的审批、取消和错误处理流程；
- Git 分支、工作区状态、差异和提交历史查看；
- 基于系统默认浏览器的网络搜索；
- 本地设置、运行日志和基础审计记录。

### 2.3 首版不纳入范围（Out of Scope）

- 跨设备同步项目文件；
- 安卓端直接访问电脑本地文件路径；
- 未经确认的远程命令执行；
- 自动扫描整个磁盘并建立完整项目数据库；
- 一开始支持所有 Git 高级操作；
- 面向团队的复杂账号、组织和权限体系；
- 将本机项目文件上传至云端作为默认行为。

上述能力应在桌面端核心流程稳定、权限模型明确后再进行评估。

### 2.4 已纳入路线图的新增模块

- 自动感知、工作痕迹记录与工作树（第 4.8 节）；
- 文件语义搜索（第 4.9 节）。

两个模块按 P1 拓展规划，在桌面端核心闭环完成后优先实施；不作为现有阶段 0–5 和 M1–M4 的新增通过条件，分别按第 11.5 节验收后开放。

## 3. 用户与典型场景

### 3.1 目标用户

- 需要同时维护多个本机项目的个人开发者；
- 使用 AI 工具辅助编码、排查问题和编写文档的开发者；
- 希望集中查看项目状态和开发任务的技术人员；
- 后续需要通过移动设备查看任务进度的高级用户。

### 3.2 典型使用场景

#### 场景 A：快速进入项目

用户启动应用后，在近期项目列表中找到目标项目，查看项目路径和 Git 分支，并通过资源管理器打开项目目录。

#### 场景 B：在项目上下文中调用 Codex

用户选择项目后输入“实现某项功能”或“修复某个问题”，应用将项目路径作为工作目录传递给 Codex，并实时展示执行状态。

#### 场景 C：审核修改结果

Codex 完成任务后，用户查看修改文件列表和差异，确认内容后在外部编辑器、资源管理器或后续 Git 流程中继续处理。

#### 场景 D：搜索技术资料

用户输入搜索关键词，应用对关键词进行编码并调用系统默认浏览器打开搜索结果。

#### 场景 E：查看项目版本状态

用户查看当前分支、工作区是否存在未提交修改、最近提交记录和文件差异。

#### 场景 F：切换 AI 运行配置

用户在桌面端选择服务源、模型和支持的思考强度。使用中转站时，选择与该站点绑定的 Key；通过连接测试后发起任务，并在任务详情中查看实际生效的配置。切回官方源并沿用原有官方认证仅作为预留功能，无需实测且结果不纳入通过判定。

#### 场景 G：自动整理工作经过

用户为项目开启自动记录后，照常打开文件、修改代码、运行任务和提交变更，无需逐条填写工作日志。应用在后台整理相关活动和产出；用户次日返回时，可沿“项目 → 任务/主题 → 活动 → 文件或提交”工作树回顾进展并继续工作。

#### 场景 H：按含义寻找文件

用户记得某份文档讲过“连接失败后如何恢复原来的配置”，但忘记文件名和具体术语。输入这段描述后，应用返回相关文档或代码片段，展示路径、命中内容和关联依据，并可直接打开原文件。

#### 场景 I：跨窗口快速发起对话

用户正在编辑器、终端或其他普通桌面窗口中工作时，无需切换到 Project Assistant 主窗口。用户点击常驻悬浮球或按全局快捷键展开输入面板，输入任务并发送；入口默认沿用主窗口最近选择的项目、会话和 AI 配置，持续展示任务状态。没有可用项目或会话上下文时，入口提示用户打开主窗口补充上下文，不直接提交任务。

## 4. 功能需求

### 4.1 项目管理模块（P0）

| 编号 | 功能 | 要求 |
| --- | --- | --- |
| FR-PM-001 | 近期项目记录 | 记录用户主动打开或使用过的项目，并按最近使用时间排序。 |
| FR-PM-002 | 项目搜索 | 支持按项目名称、路径和相关元数据进行模糊搜索。 |
| FR-PM-003 | 项目信息展示 | 展示项目名称、绝对路径、最近使用时间、Git 分支和工作区状态。 |
| FR-PM-004 | 打开项目目录 | 通过系统文件管理器打开项目所在目录。 |
| FR-PM-005 | 打开指定文件 | 支持通过系统默认程序或配置的编辑器打开文件。 |
| FR-PM-006 | 项目移除 | 允许用户从列表中移除项目记录，但不删除项目文件。 |
| FR-PM-007 | 手动添加项目 | 支持用户选择目录并将其加入项目列表。 |

### 4.2 对话与 Codex 工作流模块（P0）

| 编号 | 功能 | 要求 |
| --- | --- | --- |
| FR-CX-001 | 项目上下文绑定 | 每次 Codex 任务必须明确绑定项目和工作目录。 |
| FR-CX-002 | 会话创建 | 支持创建、恢复和结束项目相关会话。 |
| FR-CX-003 | 消息发送 | 支持发送用户指令，并展示发送状态。 |
| FR-CX-004 | 事件接收 | 接收并展示回复、进度、审批、错误和完成事件。 |
| FR-CX-005 | 任务控制 | 支持取消正在执行的任务，并在界面中反馈取消结果。 |
| FR-CX-006 | 审批流程 | 对写文件、执行命令等需要确认的操作展示操作内容并允许用户批准或拒绝。 |
| FR-CX-007 | 结果展示 | 展示最终回复、变更文件、错误信息和后续建议。 |
| FR-CX-008 | 会话历史 | 保存本地会话摘要和最近任务记录，便于用户回顾。 |
| FR-CX-009 | 全局常驻入口 | 默认显示可关闭的悬浮球；悬浮球在普通桌面窗口之上保持可见，不承诺覆盖 UAC/安全桌面、独占全屏或系统级界面。 |
| FR-CX-010 | 悬浮输入面板 | 点击悬浮球或使用全局快捷键展开输入面板；面板打开后自动聚焦输入框，支持输入、发送、换行、收起和关闭。 |
| FR-CX-011 | 活动上下文继承 | 悬浮入口默认使用主窗口最近的项目、会话、服务源、模型和思考强度；没有可用上下文时阻止提交并给出补充入口。 |
| FR-CX-012 | 常驻任务反馈 | 在悬浮入口中展示发送状态、运行进度、审批提示、错误、取消结果和简要回复；可跳转主窗口查看完整会话、差异和审批内容。 |
| FR-CX-013 | 常驻生命周期 | 支持拖动位置、收起/展开、托盘菜单关闭和重新启用；保存显示开关、位置和显示器标识，重启后恢复有效状态，异常退出后不遗留独立进程。 |

**默认交互与关闭约定**：首次启动默认启用常驻模式，以收起的悬浮球显示；后续启动沿用用户保存的启用状态。点击悬浮球或全局快捷键展开面板并聚焦输入框，展开后不会因失去焦点自动清空草稿；Enter 发送，Shift+Enter 换行，中文输入法组字期间的 Enter 不触发发送，Esc 收起。发送后保留面板展示任务反馈，由用户主动收起；收起保留当前运行期间的未发送草稿，再展开时恢复。面板关闭按钮、设置关闭和托盘关闭均停用常驻入口并保存开关，再启用可由设置或托盘完成；关闭入口不取消任务，取消须单独操作。开启常驻模式时，关闭主窗口只隐藏主窗口；关闭常驻模式后，关闭主窗口沿用退出应用的行为。主窗口和托盘均提供明确的“退出应用”入口，退出时按任务取消/清理流程关闭自有进程，不静默留在后台。默认不随系统开机启动。

Codex 集成应封装在独立服务层中。界面层不得直接依赖底层通信协议，以降低协议变化对 UI 和业务逻辑的影响。

### 4.3 AI 模型、思考强度与服务源配置模块（P0）

桌面端应允许用户在发起任务前，或在当前会话允许变更时，明确选择本次任务使用的 AI 配置。该配置分为“模型运行参数”和“服务源凭据配置”两层，避免把 Key 直接暴露在任务输入或普通日志中。

| 编号 | 功能 | 要求 |
| --- | --- | --- |
| FR-AI-001 | 模型切换 | 在桌面端提供可用模型列表和当前模型标识；列表来源于当前服务源能力探测或受版本控制的本地配置。 |
| FR-AI-002 | 思考强度切换 | 按模型和服务源能力提供思考强度选项；例如低、中、高，具体枚举以能力结果为准。不支持的选项不可选择，切换模型后重新校验并记录实际生效值。 |
| FR-AI-003 | 服务源切换（官方源预留） | 支持已配置的中转站 profile 之间切换；切换前展示服务源名称、endpoint、认证状态和默认模型。官方源相关切换仅作预留，无需实测且结果不纳入通过判定。 |
| FR-AI-004 | 中转站 profile | 支持新增、编辑、启用、停用、删除和测试中转站配置；每个 profile 至少包含名称、endpoint、协议类型、默认模型、默认思考强度和 Key 引用。 |
| FR-AI-005 | 中转站 Key 管理 | 支持新增、替换、移除和切换与站点绑定的 Key；界面仅显示配置/验证状态和版本，不回显完整 Key 或末尾片段。任务只能解析所选站点的 Key，禁止把一个站点的 Key 发送给其他站点。 |
| FR-AI-006 | 手动 cc-switch 与自管配置边界 | 用户在应用外自行管理 cc-switch；应用不自动读取、导入、同步、编辑或切换其配置/凭据，不依赖其安装或版本。应用自管 profile、Key、连接测试、模型/强度和任务快照；自有 Codex 进程使用应用专属配置，不继承或写入用户共享配置，不控制外部进程。 |
| FR-AI-007 | 配置生效范围 | 明确配置作用于新任务、当前会话或全局默认值；任务创建后保存实际使用的 profile、模型和思考强度，防止后续切换改变历史记录含义。 |
| FR-AI-008 | 连接测试与回滚 | 切换前支持连通性和认证测试；失败时保留原配置并给出可执行错误信息，不得留下半切换状态。 |

推荐界面在任务输入区附近提供“服务源 / 模型 / 思考强度”三个紧凑选择器，在设置页提供 profile 和 Key 的完整管理。默认值按“本次任务选择 > 项目配置 > 全局默认”解析，恢复会话时重新检查配置是否仍可用；失效时提示用户选择，禁止静默改用其他中转站。

官方源沿用官方登录状态、配置官方 API Key 及失效后重新认证的能力仅作预留，无需实际测试且结果不纳入通过判定。中转站的协议、模型和思考强度必须与 Codex 网关兼容；首版不承诺支持所有 AI 平台和任意协议的模型。

### 4.4 差异与结果查看模块（P0）

- 展示本次任务涉及的文件列表；
- 支持查看新增、删除和修改内容；
- 对无法读取或无法生成差异的文件显示明确原因；
- 提供“重新加载”“在编辑器中打开”和“打开所在目录”等操作；
- 差异查看不应默认替代用户的最终代码审查责任。

### 4.5 Git 集成模块（P1）

首版以只读能力为主：

- 查看当前分支；
- 查看工作区状态；
- 查看文件差异；
- 查看最近提交历史；
- 识别项目是否为 Git 仓库；
- 对 Git 未安装、目录不是仓库、权限不足和命令失败提供可理解的错误信息。

后续再增加提交、切换分支、拉取、推送、暂存和回滚等写操作，并沿用审批和审计机制。

### 4.6 网络搜索模块（P1）

- 提供搜索关键词输入框；
- 对关键词进行 URL 编码；
- 生成目标搜索引擎 URL；
- 通过 Tauri Opener 或系统能力调用默认浏览器；
- 对空关键词、无效 URL 和浏览器调用失败进行提示；
- 初期不建设独立搜索后端，不保存用户搜索内容，除非用户主动开启历史记录。

### 4.7 设置与运行记录模块（P1）

- 默认搜索引擎配置；
- 默认编辑器配置；
- Codex 连接和运行参数配置；
- 全局及项目级默认服务源、模型和思考强度（核心切换按 P0 验收）；
- 常驻模式启停、全局快捷键配置、悬浮位置与显示器恢复设置（按 P0 桌面入口验收）；
- 应用自管中转站 profile、Key 状态与手动配置说明；cc-switch 仅说明外部管理边界，不要求安装或版本检测；
- 项目列表显示和排序设置；
- 审批策略设置；
- 日志级别和日志目录配置；
- 清理本地会话摘要和运行记录。

### 4.8 自动感知、工作痕迹记录与工作树模块（P1 拓展）

**目标**：在用户一次性选择项目范围并开启后，后台自动记录工作痕迹，尽量不打断正常工作，持续整理出可查看、可修正、可续接的工作树。

这里的“工作树”指工作脉络的层级视图，与第 13.5 节的 Git worktree 并行工作目录分别建模。

| 编号 | 功能 | 要求 |
| --- | --- | --- |
| FR-WT-001 | 自动感知范围 | 采集应用内项目/文件打开、任务与会话事件，以及已启用项目目录中的文件变更和 Git 提交信息；外部编辑器的文件打开、命令执行等活动仅在后续适配器接入后记录，不承诺全系统感知。 |
| FR-WT-002 | 无感记录 | 开启后异步记录时间、项目、事件来源、关联任务、文件路径和结果摘要；合并短时间内的重复保存与批量变更，用户无需逐条登记或确认。 |
| FR-WT-003 | 工作树整理 | 按“项目 → 任务/主题 → 活动 → 产出”组织记录，关联会话、变更文件、提交和文档；允许同一产出被多个任务引用，未明确归属的活动进入待归类节点。 |
| FR-WT-004 | 自动关联与纠正 | 优先使用明确的项目、任务和会话关联，再按时间、路径和内容线索辅助归类；推断关系展示依据及不确定性，支持重命名、移动、合并、拆分节点，后续自动整理保留用户修正。 |
| FR-WT-005 | 回顾与续接 | 支持按日期、项目、任务和活动类型筛选，展开查看事件依据和产出，打开原文件、查看提交或恢复已有会话；自动摘要可追溯到原始记录，不把文件变化直接判定为任务完成。 |
| FR-WT-006 | 记录控制与留存 | 提供项目级开关、暂停/恢复、排除规则、保留期限和删除入口；删除记录时同步清理派生摘要及关联索引，不删除用户源文件。暂停或应用退出期间的活动不伪造补录。 |

首期记录在应用运行期间进行，可在用户启用托盘常驻后继续；重启后的目录核对仅标记为“离线期间发现的变化”，不推断精确操作时间、操作者或工作时长。默认仅保存事件元数据和必要摘要，不持续保存文件全文或屏幕、键盘、剪贴板内容；敏感路径和凭据文件排除在自动采集范围之外。

### 4.9 文件语义搜索模块（P1 拓展）

**目标**：让用户按文件内容的含义和用途查找资料，不必准确使用文件名、函数名或原文关键词。

| 编号 | 功能 | 要求 |
| --- | --- | --- |
| FR-SS-001 | 自然语言查询 | 支持描述用途、问题或大致内容，例如“处理登录过期的代码”“失败后恢复配置的说明”；同义表达和无原词重合的查询也应能检索相关内容。 |
| FR-SS-002 | 内容索引 | 对用户选择的项目或目录建立文件内容索引；首期支持可提取文本的代码、Markdown、纯文本和配置文件，按内容分块并保留路径、位置和版本信息；PDF、Office 和图片 OCR 留作后续解析扩展。 |
| FR-SS-003 | 混合检索 | 结合语义向量、全文关键词和文件名/路径匹配排序，既支持模糊意图，也保留精确名称查找；支持按项目、目录、文件类型和修改时间过滤。 |
| FR-SS-004 | 结果可追溯 | 返回文件路径、相关片段、匹配依据及索引更新时间，支持打开文件并在编辑器支持时定位到对应位置；结果基于实际存在且有权限访问的文件，不生成虚构文件或引用。 |
| FR-SS-005 | 增量更新 | 文件新增、修改、移动或删除后增量更新索引；提供索引进度、暂停、重建和清理入口，识别过期结果；模型或分块规则变化时按版本重建，避免混用不兼容向量。 |
| FR-SS-006 | 本地优先与降级 | 默认在本地解析、生成向量和检索；本地模型未就绪或索引失败时明确提示，并保留关键词/路径搜索。远端向量服务须由用户另行配置并明确授权内容发送范围，不自动复用对话服务源。 |
| FR-SS-007 | 工作上下文联动 | 搜索结果可关联工作树中的任务和活动；用户选择后可作为 Codex 任务上下文，展示将附加的文件片段及范围。文件搜索可独立启用，不依赖工作痕迹采集开关。 |

索引遵循项目边界、忽略规则与敏感文件排除配置，默认排除依赖、构建产物和凭据文件；权限撤销或目录移出搜索范围后，立即停止返回相关结果并清理对应片段与向量。无合适结果时明确提示，并允许调整查询或使用关键词搜索。

## 5. 非功能需求

### 5.1 安全性

- 所有本地文件操作必须使用规范化后的绝对路径；
- 禁止未经校验的路径拼接和目录穿越；
- 命令执行优先使用参数数组，避免通过字符串拼接构造 Shell 命令；
- 高风险操作必须经过用户确认；
- 默认不扫描整个磁盘；
- 默认不上传项目文件；
- 日志中不得明文记录访问令牌、密码和其他敏感信息；
- 远程能力上线前必须建立设备认证、权限控制、过期机制和高风险操作二次确认。

### 5.2 可用性

- 项目、技能、任务和设置入口应保持清晰；
- 任务执行期间应持续展示当前状态，避免让用户误以为应用无响应；
- 所有失败场景应给出原因和可执行的处理建议；
- 关键操作应支持取消或返回；
- 应用重启后应保留项目元数据和必要的会话摘要。
- 常驻悬浮球默认开启且可在设置或托盘中关闭；输入面板展开后必须自动获得焦点，不要求用户切换到主窗口。
- 悬浮入口应支持键盘完成主要操作，并在被系统窗口遮挡、置顶失败或上下文失效时给出可执行提示。

### 5.3 性能目标

- 应用启动后优先展示本地缓存的近期项目；
- 常规项目搜索应在可接受的交互延迟内返回结果；
- Git 状态查询和文件差异读取应采用异步方式，避免阻塞主界面；
- 大型项目、超大文件和超长日志应采用分页、截断或按需加载；
- Codex 事件流应支持增量展示，避免等待任务结束后一次性刷新。
- 悬浮球和输入面板的展开、聚焦与状态刷新应保持交互响应，不阻塞主窗口、Codex 事件流或后台任务。

### 5.4 可维护性

- 前端、Rust 服务层和外部适配器应保持边界清晰；
- 文件系统、Git、Codex、浏览器和同步服务分别封装；
- 重要数据结构和 IPC 接口采用明确的 TypeScript/Rust 类型；
- 对外部进程调用统一进行超时、退出码和错误输出处理；
- 为核心流程提供单元测试、集成测试和端到端测试。

### 5.5 AI 配置与凭据安全

- 模型、思考强度、服务源和 Key 必须使用结构化配置，不得通过拼接命令或未校验的环境变量传递；
- 中转站 Key 不得明文写入普通日志、任务提示词、会话摘要、错误消息或差异内容；
- 本应用的普通数据库只保存 profile 元数据、Key 引用和状态；自管 Key 使用系统凭据库，不读取或复用 cc-switch 凭据；凭据库不可用时拒绝使用，不降级明文；
- 配置读取、切换、测试、失败和回滚均记录审计事件，但审计内容只保留 profile ID、模型、思考强度、结果和关联 ID；
- 任务开始后固定实际使用的服务源、模型和思考强度，后续全局切换不得修改历史任务记录；
- cc-switch 未安装、版本变化或外部配置损坏不影响应用自管 profile；应用内 profile/Key 失效时禁止新任务启动并提示修复，不静默换源；
- 日志、诊断包、备份和导出必须排除完整 Key；发送前校验 endpoint 与 Key 所属站点一致，不向意外的跨站重定向地址转发凭据。

## 6. 产品流程与状态模型

### 6.1 核心流程

启动应用 → 加载本地项目索引 → 选择或搜索项目 → 查看项目摘要、打开目录或查看 Git 状态 → 选择技能（Codex 或网络搜索）→ 若调用 Codex，选择并校验服务源、模型和思考强度 → 执行任务或打开搜索结果 → 展示进度、审批、错误和结果 → 查看文件差异并继续后续开发。

### 6.2 Codex 任务状态

建议统一使用以下状态：

- idle：尚未开始；
- preparing：正在准备工作目录和会话；
- running：任务执行中；
- approval_required：等待用户审批；
- cancelling：正在取消；
- completed：任务完成；
- failed：任务失败；
- cancelled：任务已取消。

状态变化应由服务层统一管理，前端只负责展示和触发用户操作。

### 6.3 AI 配置状态

AI 配置建议使用以下状态：

- `unconfigured`：尚未配置可用服务源；
- `checking`：正在检查应用自管服务源、模型能力或 Key；
- `ready`：配置完整且最近一次连接测试成功；
- `switching`：正在切换 provider、模型或思考强度；
- `degraded`：配置可读取，但模型列表、思考强度或连接测试结果不完整；
- `error`：配置不可用，展示回滚结果；没有可用配置时阻止任务启动。

任务详情至少展示：服务源名称、模型、思考强度、配置生效时间和任务启动时的配置快照。

## 7. 技术方案

### 7.1 总体技术栈

| 层级 | 推荐方案 | 主要职责 |
| --- | --- | --- |
| 桌面框架 | Tauri 2 | 窗口、系统集成、桌面与后续安卓扩展基础。 |
| 桌面入口 | Tauri 独立 overlay window、全局快捷键与系统托盘 | 悬浮球常驻、输入面板展开/收起、置顶、位置恢复、启停控制和主窗口同步。 |
| 前端 | React + TypeScript | 项目列表、搜索、对话、任务状态和差异界面。 |
| 本地服务层 | Rust | 文件系统、进程、Git、Codex 通信和安全校验。 |
| 本地数据库 | SQLite | 项目元数据、会话摘要、设置和审计记录。 |
| 搜索 | 应用层模糊搜索；必要时使用 SQLite FTS5 | 项目和本地数据检索。 |
| 文件语义检索（拓展） | 文本分块、本地向量模型与向量索引，结合全文检索 | 按内容含义搜索文件；模型和索引实现经资源占用、检索质量验证后选型。 |
| Git | 系统 Git CLI | 首版读取分支、状态、差异和历史。 |
| 浏览器 | Tauri Opener / 系统默认浏览器 | 打开项目目录、文件和搜索 URL。 |

推荐组合：**Tauri 2 + React + TypeScript + Rust + SQLite**。

### 7.2 Codex 集成方案

- 优先通过本机可用的 Codex app-server 能力建立通信；
- 通信方式可采用 stdio 或项目实际可用的 SDK/协议实现；
- 以选定项目路径作为工作目录；
- 在服务层统一处理会话、事件、超时、取消和错误；
- 对审批请求提供可审阅的操作摘要；
- 以事件驱动方式向前端推送增量状态；
- 对具体协议字段进行版本适配，避免业务层散落协议细节。

Codex 网关不得直接把官方源和中转站逻辑散落到任务代码中。采用 `provider_manager` 与自管配置适配器：

- `provider_manager` 维护当前有效 profile、模型和思考强度，并为任务生成不可变的运行配置快照；
- 自管配置适配器从应用仓储和系统凭据服务生成自有进程配置；模型与思考强度通过 Codex 网关和 profile 能力配置解析，连接测试由服务层统一编排；
- 官方源和中转站统一抽象为 provider profile，区别仅体现在认证方式、endpoint、协议能力和模型目录；
- 不建设 cc-switch 自动适配器，不调用其内部数据库、Tauri 命令、深链或社区 CLI，不自动导入用户共享 Codex 配置；用户在设置页手动填写应用 profile 与 Key；
- 每个受管理进程使用应用专属 CODEX_HOME、明确的 endpoint/协议和受控环境；清除继承的认证/provider/代理覆盖，验证项目配置不能覆盖所选来源。拒绝依赖 cc-switch 共享可变代理/接管路由的配置，无法证明路由隔离时不启动任务；进程隔离不等于网络路由隔离；
- 默认串行复用自有进程；切换默认值影响未来任务，既有任务继续使用原快照。需要替换进程配置或移除/替换受占用凭据时排队等待自有任务空闲，只重建自有进程/会话；多 profile 并行须另验隔离；
- 核实配置加载时机和进程归属，必要时只重启本应用管理的空闲进程或重建会话。禁止静默中断本应用或外部 Codex 任务；
- 连接测试和切换操作必须支持超时、取消、失败回滚和结果校验。

常驻对话入口使用独立的 overlay window，与主窗口共享类型化的活动上下文和任务事件。overlay window 默认置顶于普通桌面窗口，可拖动并记住位置和显示器标识；全局快捷键只负责展开/聚焦入口，不推断当前前台应用对应的项目。关闭悬浮入口不应终止主窗口或正在运行的任务，退出应用时必须同时关闭 overlay window、托盘驻留和相关监听器。

悬浮球与展开面板复用同一 overlay window，以防重复创建入口；服务层维护活动项目、会话、脱敏 AI 选择和任务状态，两个窗口通过现有版本化 IPC 获取快照与增量事件，重建窗口或发现事件缺口后重新查询。发送前在服务层校验并固定上下文与配置快照；主窗口后续切换不改变已提交任务，双重提交须防重。窗口 capability 按入口职责分别授权，overlay 不接入 Key 管理或直接执行高风险审批，审批只显示提示并定位主窗口；关闭入口不会授予额外权限。

全局快捷键默认使用 Ctrl+Alt+Space，并允许用户修改；注册冲突时提示更换组合，悬浮球点击入口仍可用。启动、任务状态更新和窗口恢复不主动抢占其他应用焦点，仅用户展开时聚焦；普通窗口置顶失败可从托盘重新唤起并提示恢复。位置按当前显示器工作区和缩放校正，显示器断开或保存位置越界时将入口移回主显示器可见区域。未发送草稿只保留在本次运行内存，不写入日志或额外持久化；日志仅记录必要的生命周期结果和关联 ID，不记录提示词、回复内容、Key、窗口坐标或前台应用信息。

### 7.3 模块划分

src/

│  ├─ semantic_search/       # 文件解析、分块、向量索引和混合检索（拓展）
│  ├─ filesystem/            # 路径校验、文件和目录操作
│  ├─ codex_gateway/         # Codex 会话与事件适配
│  ├─ ai_config/             # 模型、思考强度、provider profile 与运行快照
│  ├─ self_managed_config/   # 应用专属配置、凭据绑定与自有进程隔离

└─ storage/                  # SQLite 访问与迁移

实际目录结构可根据初始化模板调整，但应保持上述职责边界。

### 7.4 数据结构建议

首版建议至少包含以下数据表：

- projects：项目路径、名称、显示名称、创建时间和更新时间；
- project_usage：最近打开时间、打开次数和最近使用来源；
- sessions：Codex 会话标识、项目标识、摘要、状态和时间；
- tasks：任务提示、开始时间、结束时间、状态和错误摘要；
- approvals：操作类型、操作摘要、审批结果和审批时间；
- settings：用户配置和版本信息；
- audit_events：高风险操作、结果和必要的上下文摘要。
- provider_profiles：官方源/中转站名称、endpoint、协议能力、默认模型、Key 引用、启用状态和更新时间；
- model_capabilities：provider profile 可用模型、思考强度、上下文限制、来源版本和更新时间；
- ai_config_snapshots：任务启动时实际使用的 provider、模型、思考强度、配置版本和脱敏标识。

项目元数据与项目文件分离保存。应用只记录索引信息，不默认复制或上传项目内容。

两个新增模块实施时，通过后续数据库迁移补充 `activity_events`（事件与来源）、`work_nodes`（工作树节点）、`work_links`（活动、任务及产出关联）、`indexed_files`（文件版本与索引状态）和 `file_chunks`（内容分块与位置）；向量索引记录分块 ID、模型及版本。文本片段和向量属于可重建的本地派生数据，遵循原文件的访问范围与删除策略；不在当前阶段 0 schema v1 中提前加入未实现的表。

事件采集与文件检索共用目录边界和排除规则，分别控制启停。采集、归类和索引在后台异步执行，采用去重、批处理及资源限额；语义检索先验证本地模型可用性、磁盘/内存占用和检索质量，再确定模型与向量存储实现。

### 7.5 手动 cc-switch 与应用自管 profile 边界

cc-switch（https://github.com/farion1231/cc-switch/blob/main/README_ZH.md）是用户自行管理的外部工具。用户可以继续用它管理其他 Codex 客户端；本应用不检测其选中项、不自动同步配置或 Key，也不要求用户将本应用 profile 切回 cc-switch。

用户在本应用中手动创建 profile 并单独提交 Key，由系统凭据服务保存。历史桌面版 4.0.6 / 社区 CLI 5.11.0 调查仅保留证据，不作为产品依赖或验收入口。原自动接入要求已由 FR-AI-006 和 ADR-0011 替代，不能把范围调整记成自动集成实测通过。

模型能力发现和任务参数的官方参考入口为 https://developers.openai.com/codex/app-server 。本计划不固定模型名称、思考强度枚举或未经实测的协议字段，全部在步骤 0.3 验证后纳入接口契约。

## 8. 权限与安全设计原则

### 8.1 操作分级

| 风险级别 | 示例 | 默认处理 |
| --- | --- | --- |
| 低风险 | 读取项目列表、读取 Git 分支、打开目录 | 可直接执行并记录日志。 |
| 中风险 | 读取大量文件、生成差异、运行测试 | 根据策略执行，必要时提示用户。 |
| 高风险 | 写入文件、执行命令、删除文件、切换分支 | 展示操作摘要并等待用户确认。 |
| 极高风险 | 推送代码、远程命令、修改权限或凭据 | 默认关闭，需显式开启并二次确认。 |

### 8.2 远程能力原则

安卓端或其他设备不得直接假设能够访问桌面端路径。远程访问应通过桌面端本地代理完成，并至少包含：

- 已授权设备登记；
- 短期访问令牌和刷新机制；
- 设备撤销能力；
- 最小权限角色；
- 请求过期和重放防护；
- 高风险操作的桌面端确认；
- 远程操作审计记录。

## 9. 分阶段实施计划

### 阶段 0：方案确认与技术验证

**目标**：确认关键外部依赖和最小架构。

- 验证 Git CLI、系统文件管理器和浏览器调用；
- 确认 SQLite 数据结构和迁移方案；
- 输出权限、错误处理和日志规范。

**交付物**：技术验证原型、接口约定、数据模型初稿和风险清单。

### 阶段 1：桌面端基础

**目标**：建立可运行的桌面应用骨架。

**主要工作**：

- 完成基本窗口、导航和设置页面；
- 建立前端与 Rust 服务层的 IPC 通道；
- 接入 SQLite；
- 完成基础日志和错误提示；
- 建立统一的类型和事件模型。
- 建立默认开启的悬浮球、独立输入面板、全局快捷键和托盘启停控制；保存位置、显示器标识和启用状态。
- 建立 AI 配置页、profile 元数据和 Key 安全引用的基础服务；
- 明确 cc-switch 外部手动管理说明，应用配置流程独立于其安装和版本。

**验收标准**：应用能够启动、保存设置、调用本地服务，并显示可展开的常驻悬浮球；悬浮入口可在普通桌面窗口之上恢复、关闭和重新启用，异常时保持可恢复。

**分步实施入口**：见第 21 章“阶段 1 分步实施方案”。阶段 0 已按替代范围允许启动；阶段 1 各项生产能力仍须独立实施和验收。

### 阶段 2：项目发现与搜索

**目标**：完成项目管理闭环。

**主要工作**：

- 记录用户主动打开的项目；
- 展示近期项目列表；
- 实现名称和路径模糊搜索；
- 支持手动添加、移除和打开项目；
- 展示基础 Git 信息。

**验收标准**：用户能够从启动应用到找到并打开目标项目，且不需要扫描整个磁盘。

### 阶段 3：Codex 工作流

**目标**：完成 AI 辅助开发核心闭环。

**主要工作**：

- 封装 Codex 会话和事件通信；
- 完成服务源、模型和思考强度选择器，校验组合能力并保存任务配置快照；
- 实现应用自管中转站及站点 Key 切换、连接测试、自有进程等待空闲与失败恢复；不操作 cc-switch，官方源相关能力仅作预留；
- 传递选定项目的工作目录；
- 展示回复、进度、审批、错误和完成状态；
- 支持取消任务；
- 展示文件变更和差异；
- 保存必要的会话摘要。
- 将对话入口接入悬浮输入面板，沿用主窗口最近活动上下文，并在悬浮入口中反馈任务状态、错误、取消结果和简要回复。

**验收标准**：用户能够在指定项目中选择非官方服务源、模型和受支持的思考强度，切换中转站及对应 Key，发起任务、完成审批、查看实际配置与结果并定位变更文件；也可在不切换主窗口的情况下通过悬浮球或全局快捷键发起任务并查看状态。切换失败可恢复，运行中的任务不会被静默中断。官方源相关功能仅作预留，无需实测且测试结果不纳入通过判定。

### 阶段 4：Git 与网络搜索

**目标**：补充开发辅助能力。

**主要工作**：

- 接入 Git 分支、状态、差异和历史；
- 接入系统默认浏览器和搜索引擎；
- 增加命令失败、超时和权限不足处理；
- 完成核心功能的跨环境测试。

**验收标准**：用户能够在不离开应用的情况下查看项目基本版本状态，并快速发起网络搜索。

### 阶段 5：稳定性与发布准备

**目标**：达到可供目标用户试用的质量标准。

**主要工作**：

- 完成端到端测试和异常恢复测试；
- 完善日志、诊断信息和用户反馈入口；
- 优化大型项目和长任务的性能；
- 完成安装包、升级和数据迁移验证；
- 形成用户文档和发布说明。

### 阶段 6：移动端与远程能力（后续）

**目标**：在桌面端稳定后扩展跨设备能力。

**主要工作**：

- 复用前端界面并适配安卓交互；
- 建立账号、设备和权限模型；
- 同步项目元数据、设置、任务状态和会话摘要；
- 实现远程查看任务状态；
- 最后再评估远程控制和高风险操作。

## 10. 里程碑与验收标准

### M1：可运行桌面原型

## 11. 测试与质量保证

### 11.1 测试类型

- **单元测试**：路径校验、搜索、Git 输出解析、状态转换和策略判断；
- **集成测试**：SQLite、系统打开能力、Git CLI 和 Codex 适配层；
- **端到端测试**：从启动应用到项目选择、任务执行和差异查看；
- **常驻入口测试**：普通窗口置顶、快捷键冲突、中文输入、上下文同步、托盘启停、多显示器与缩放、关闭退出和异常恢复；
- **异常测试**：进程中断、权限不足、目录删除、网络不可用和超时；
- **安全测试**：路径穿越、命令注入、敏感信息泄露和审批绕过；
- **兼容性测试**：不同 Windows 环境、Git 安装状态和常见项目类型。

### 11.2 发布门槛

- P0 功能流程完整可用；
- 高风险操作均具备明确确认机制；
- 关键异常不会导致应用崩溃或数据损坏；
- 日志能够支持问题定位，但不泄露敏感信息；
- 数据库升级和回滚方案经过验证。

### 11.3 全局常驻对话入口验收用例

以下用例验证悬浮球、输入面板、全局快捷键、上下文继承和常驻窗口生命周期；当前仅为验收计划。

| 用例 | 前置条件与操作 | 期望结果 |
| --- | --- | --- |
| AT-CX-001 默认常驻与关闭 | 启动应用；从设置或托盘关闭悬浮入口，再重新启用并重启应用 | 首次启动默认显示悬浮球；关闭后不再显示；重新启用和重启后状态、位置与显示器标识正确恢复。 |
| AT-CX-002 展开与输入 | 在编辑器或终端中点击悬浮球或使用全局快捷键；输入文本、中文组字、换行、发送、收起和关闭；模拟快捷键冲突 | 无需切换主窗口即可输入和发送；展开后自动聚焦，Enter 发送、Shift+Enter 换行，组字 Enter 不误发送；草稿收起后可恢复，发送后反馈仍可见；关闭保存停用状态，不终止既有任务；快捷键冲突有提示且点击可用。 |
| AT-CX-003 活动上下文 | 在主窗口选择项目、会话、服务源、模型和思考强度后，从其他普通窗口展开悬浮入口并提交 | 请求继承主窗口最近活动上下文；没有可用上下文时阻止提交并提示打开主窗口补充。 |
| AT-CX-004 任务反馈 | 从悬浮入口发起任务，观察进度、审批、错误、取消和完成状态 | 悬浮入口持续展示状态与简要回复；完整会话、差异和审批内容可跳转主窗口查看；主窗口与悬浮入口状态一致。 |
| AT-CX-005 置顶与显示器 | 拖动悬浮球，在多个普通窗口、不同缩放显示器之间移动；断开显示器，模拟窗口重建、置顶失效和异常退出 | 悬浮球与输入面板保持普通窗口置顶；重建后只有一个入口且状态同步；越界位置移回可见区域；失败可从托盘恢复，不自动抢焦点，退出不遗留自有进程。 |
| AT-CX-006 置顶边界与日志 | 打开 UAC/安全桌面、独占全屏场景；检查日志/诊断中的提示词、Key、任务结果和窗口状态 | 不承诺覆盖或修改不支持的系统界面；日志/诊断不含提示词、回复、Key、坐标或前台应用信息，仅保留必要生命周期结果和关联 ID。 |
| AT-CX-007 主窗口关闭与退出 | 常驻开启/关闭时分别关闭主窗口；由托盘重新打开；任务运行中关闭悬浮面板，再从主窗口或托盘退出应用 | 常驻开启时主窗口隐藏且悬浮入口可用，停用时关闭主窗口退出应用；关闭面板不取消任务；明确退出后按既有清理流程结束自有进程并注销托盘和监听器。 |

### 11.4 自管 AI 配置与外部手动管理验收用例

| 用例 | 前置条件与操作 | 期望结果 |
| --- | --- | --- |
| AT-AI-001 模型与思考强度 | 从可用模型切换到另一模型并选择支持的强度，再发起任务 | 请求参数、界面和任务快照一致；不支持的组合禁用，失效选项提示重新选择。 |
| AT-AI-002 官方/中转站切换（预留） | 仅作预留，无需实际测试 | 不考虑其测试结果；未测试、失败或历史结果不影响测试、阶段验收及发布是否通过，不构成阻塞，也不记为实测通过。 |
| AT-AI-003 多站点与 Key | 两个中转站分别绑定不同 Key，并替换或切换其中一站的 Key | 仅选中站点使用绑定 Key；不存在跨站发送或完整 Key 回显。 |
| AT-AI-004 失败与回滚 | 使用错误 Key、无效 endpoint、超时或注入切换写入失败 | 返回脱敏错误，未提交失败配置；已发生部分变更时回滚并校验，无法回滚时阻止新任务并提供恢复入口。 |
| AT-AI-005 运行中切换与隔离 | 任务运行时切换应用默认 profile；需重建自有进程时等待空闲；用户在应用外手动切换 cc-switch | 既有任务保留原路由/模型/Key，后续任务采用新配置；不监控或同步 cc-switch，不改写共享配置或中断外部任务；共享可变代理或未核验覆盖配置被拒绝。 |
| AT-AI-006 重启与配置失效 | 重启应用；模拟 cc-switch 未安装/升级及应用模型、profile 或凭据失效 | 有效自管默认值可恢复并重新校验；cc-switch 状态不构成依赖；应用无效配置不静默替换，原可用配置继续使用。 |
| AT-AI-007 密钥泄露检查 | 检查 IPC 返回、日志、错误、历史、诊断包、备份和导出 | 不含完整 Key；普通数据库只保留安全引用，网络测试不向错误站点或跨站重定向发送 Key。 |
| AT-AI-008 外部配置边界 | 使用隔离外部配置夹具；分别模拟无 cc-switch、桌面升级、外部 config/auth 改动和继承环境/项目配置覆盖 | 应用不读取外部 profile/Key、不依赖内部表或社区 CLI、不写共享配置；实际请求仅使用显式自管来源，隔离无法核验时返回固定错误并拒绝启动。 |

优先使用受控测试服务验证参数和认证路由，不在日志中保存真实 Key；真实服务连接测试使用最小请求，不宣称通过连通测试即可验证所有模型能力。

### 11.5 工作树与文件语义搜索验收用例（拓展上线门槛）

以下用例在对应模块实现后执行，当前仅为验收计划。

| 用例 | 前置条件与操作 | 期望结果 |
| --- | --- | --- |
| AT-WT-001 无感记录 | 启用测试项目记录，连续保存文件、执行应用内任务并创建 Git 提交 | 无需逐条填写日志即可生成带来源和时间的活动，重复保存被合并，任务、文件与提交可关联并回溯。 |
| AT-WT-002 工作树纠正 | 并行处理两个任务，产生同一文件的修改及无明确任务的活动；手动移动或拆分节点后重启并继续记录 | 不强制把模糊活动归入某个任务；推断有依据，待归类节点可处理，用户修正持久保存且不被自动整理覆盖。 |
| AT-WT-003 范围与留存 | 暂停记录、修改排除目录文件、退出期间修改文件，再恢复；删除指定日期记录 | 暂停和排除范围不采集；离线变化不伪造操作时间；删除后对应摘要与关联索引被清理，源文件保留。 |
| AT-SS-001 语义相关性 | 固定至少 20 组“查询—相关文件”样例，其中至少一半使用同义表达或不含目标原文关键词的描述 | 总体及无原词重合子集的 Top-5 命中率均不低于 80%；固定语料、模型和索引版本，报告未命中样例，不用关键词结果冒充语义检索通过。 |
| AT-SS-002 结果与更新 | 搜索后修改、移动、删除命中文件，并等待索引任务完成 | 片段、路径和位置与当前文件一致；删除文件不再返回，更新期间显示索引状态，精确名称搜索仍可用。 |
| AT-SS-003 范围与降级 | 查询排除文件、撤销目录访问、移除索引范围，再模拟本地模型不可用 | 无越界结果；对应片段与向量被清理；模型失败有提示且关键词/路径搜索可用，未授权时无文件内容外发。 |
| AT-WS-001 独立运行与资源 | 分别单独开启两个模块，再在大型测试项目中同时启用并触发批量变更 | 搜索不依赖记录开关，记录不依赖向量模型；后台任务可暂停、可恢复，不阻塞前台操作，记录测试规模、资源峰值和查询延迟。 |

## 12. 主要风险与应对措施

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| Codex 通信协议或事件模型变化 | 影响核心工作流 | 通过独立网关封装，增加版本适配和集成测试。 |
| 外部配置或共享可变代理侵入任务路由 | 自管快照与实际请求不一致 | cc-switch 仅外部手动管理；应用专属 home、受控环境与实际路由核验；拒绝共享接管路线，不读取/写入外部配置，功能上线前验证 AT-AI-005/008。 |
| 模型与思考强度能力差异 | 参数被拒绝或实际效果与界面不一致 | 按服务源与模型探测并校验，不支持的组合禁用，失效时要求重新选择。 |
| 自管配置、路由变更或重启影响任务 | 任务被中断或请求误用新服务源 | 默认值只作用于未来任务；进程/凭据变更等待自有任务空闲，拒绝共享可变代理和未核验覆盖；并行 profile 需另验隔离，不同步 cc-switch。 |
| 中转站 Key 泄露或绑定错误 | 凭据泄露或错误计费 | 安全引用、站点绑定、脱敏、导出排除和切换回滚；核实外部凭据存储保护。 |
| 外部进程卡死或异常退出 | 界面无响应、任务状态不一致 | 使用异步调用、超时、取消和进程生命周期管理。 |
| 文件权限和路径差异 | 无法读取或写入项目 | 统一规范化路径，提供清晰错误信息并限制访问范围。 |
| 项目包含敏感信息 | 造成信息泄露 | 默认本地处理、最小化日志、敏感字段脱敏和审批机制。 |
| Git 环境差异 | 状态解析失败 | 优先使用稳定的结构化输出，并对版本和错误输出做兼容处理。 |
| 大型项目或超长日志 | 性能下降、内存占用过高 | 增量加载、分页、截断和按需读取。 |
| 悬浮入口焦点、置顶与跨窗口状态差异 | 误发送任务、遮挡工作区或入口不可达 | 用户展开时才聚焦；发送前固定上下文；支持关闭、拖动、快捷键冲突提示、显示器位置修正和服务层统一同步，按 AT-CX-001–007 复验。 |
| 远程控制权限过大 | 产生严重安全后果 | 远程能力后置，采用设备认证、最小权限和桌面端确认。 |

## 13. 拓展功能建议（供后续评估参考）

以下功能除标为“已纳入 P0”的 EX-A-02 外，不属于首版硬性范围，可依据用户反馈、技术成本和安全风险分阶段纳入产品路线图。

### 13.1 高优先级拓展

#### A. 项目工作区增强

- **项目健康检查**：检测 Git 状态、依赖安装、运行环境和常用脚本是否可用；
- **项目摘要卡片**：展示技术栈、入口文件、启动命令、最近提交和未完成任务；
- **项目书签**：保存常用文件、目录、命令和文档入口；
- **项目模板**：为不同项目类型预设初始化检查和常用操作；
- **项目分组与标签**：按客户、语言、状态或优先级组织项目。

**价值**：提高项目切换效率，减少重复寻找入口和环境检查的时间。

#### B. 本地开发工具集成

- **内置终端**：在当前项目工作目录中打开终端，并显示命令执行结果；
- **运行配置**：保存开发、测试、构建和预览命令；
- **测试入口**：一键运行单元测试、集成测试或指定测试文件；
- **日志查看器**：聚合开发服务器、测试和构建日志；
- **环境变量管理**：仅保存变量名称和安全引用，不在普通界面明文展示敏感值。

**价值**：减少在多个终端、编辑器和文件管理器之间切换的频率。

#### C. 任务与会话管理

- **任务历史**：按项目查看 Codex 任务、状态、耗时和变更文件；
- **任务标签**：标记“功能开发”“缺陷修复”“重构”“文档”等类型；
- **任务收藏**：保存高价值提示词和成功案例；
- **任务续接**：从历史会话摘要恢复上下文；
- **任务导出**：导出任务摘要、差异和审批记录，便于归档或提交评审。

**价值**：让 AI 辅助开发从一次性对话变成可追踪的项目任务流程。

#### D. 本地代码与文档搜索

- 文件内容检索按第 4.9 节独立语义搜索模块实施，支持自然语言和同义描述，无需准确关键词；
- 在项目范围内搜索代码、配置、文档和提交信息；
- 支持按文件类型、目录、分支和修改时间过滤；
- 对常用文档建立本地索引；
- 将搜索结果作为 Codex 任务上下文；
- 支持排除构建目录、依赖目录和敏感目录。

**价值**：提升查找项目上下文和准备 AI 任务的效率。

### 13.2 中优先级拓展

#### E. AI 工作流增强

- **任务规划模式**：先生成实施计划，用户确认后再修改文件；
- **只读分析模式**：仅允许读取和分析，不允许写入或执行命令；
- **代码审查模式**：根据差异生成风险、规范和测试建议；
- **测试修复闭环**：运行测试、收集错误、生成修复建议并等待确认；
- **上下文包**：由用户选择文件、目录或搜索结果，形成可复用任务上下文；
- **自动模型/策略路由**：在第 4.3 节首版手动切换的基础上，根据任务类型自动推荐模型、工具权限或审批策略；
- **多任务队列**：允许用户排队执行多个低风险任务，并逐个查看结果。

**价值**：提升任务质量，同时让用户更清楚地控制 AI 的权限边界。

#### F. Git 与代码评审增强

- 提交前检查和提交信息生成；
- 分支比较和变更摘要；
- 暂存区管理；
- 变更风险分析；
- 生成 Pull Request 描述；
- 关联 issue、任务编号或发布说明；
- 对提交、推送和回滚提供强制确认。

**价值**：把项目助手从“查看 Git 信息”扩展为“辅助完成版本管理”。

#### G. 插件与技能系统

- 定义统一的技能描述、输入参数和权限声明；
- 支持安装、启用、停用和卸载技能；
- 为技能提供沙箱或权限范围；
- 支持项目级和全局级技能配置；
- 记录技能执行日志和版本信息；
- 建立技能兼容性和安全审核机制。

**价值**：让产品能够在不修改核心代码的情况下接入更多开发工具和业务流程。

#### H. 自动化与触发器

- 项目打开时自动执行健康检查；
- Git 状态变化时刷新项目摘要；
- 测试失败时生成分析任务；
- 定时检查依赖更新或构建结果；
- 根据文件变化触发格式化、测试或索引更新；
- 支持用户自定义“如果发生 X，则执行 Y”的规则。

**价值**：将重复性工作变成可控的自动化流程。所有自动化任务应具备可暂停、可查看和可撤销能力。

### 13.3 长期拓展

#### I. 安卓端与跨设备同步

- 同步项目名称、路径别名、标签和设置；
- 同步任务状态、会话摘要和审批请求；
- 支持移动端查看任务进度和完成结果；
- 支持移动端发送低风险指令；
- 不直接同步完整项目文件，除非未来建立明确的云端存储方案。

#### J. 远程查看与远程控制

建议分为三个阶段：

1. **只读阶段**：远程查看项目列表、任务状态和日志摘要；
2. **受限交互阶段**：批准低风险操作、暂停任务或发送补充消息；
3. **高风险阶段**：在桌面端在线确认和严格策略控制下执行命令、写文件或 Git 操作。

#### K. 团队协作

- 共享任务模板和项目规范；
- 团队级技能和审批策略；
- 任务评论、交接和责任人；
- 项目活动时间线；
- 团队操作审计和权限报表。

该方向需要重新评估账号、组织、数据隔离和合规要求，不建议在个人桌面版稳定前实现。

#### L. 智能知识库

- 自动整理项目文档、架构说明和常见问题；
- 将历史任务、提交和文档关联起来；
- 支持基于项目上下文的问答；
- 支持知识条目版本和来源追踪；
- 对敏感目录提供排除和访问控制。

### 13.4 入口与效率

> 本组除 EX-A-02 已纳入 P0 外，可在首版核心闭环稳定后优先评估；常驻入口还涉及窗口生命周期、跨窗口 IPC 与系统权限，按第 4.2、7.2 和 11.3 节实施验收。

#### EX-A-01 命令面板（Quick Actions）

- **说明**：提供类 `Ctrl+K` 的统一入口，在一个面板内完成切换项目、发起任务、打开目录、搜索和修改设置。
- **价值**：用一个入口串联全部高频操作，是降低路径查找与上下文切换成本的核心杠杆。
- **依赖与成本**：复用现有项目索引与技能注册表，无需新增基础设施，成本低。
- **风险**：可能与系统或编辑器的全局快捷键冲突；条目来源需收敛，避免膨胀为「什么都能做」。

#### EX-A-02 全局唤起与托盘常驻（已纳入 P0）

- **定位**：已吸收为首版 P0 常驻对话入口（FR-CX-009–013），保留原编号供追溯，不再作为后续拓展单独排期。
- **交付与验收**：阶段 1 完成悬浮窗口、全局快捷键、托盘和设置恢复；阶段 3 接入活动上下文与真实任务。功能与边界统一按第 4.2、7.2、11.3 和 21 章执行。

#### EX-A-03 IDE 集成与自定义 URI 协议

- **说明**：支持 `vscode://`、JetBrains 等协议，并注册自有 `projectassistant://` 协议，从编辑器反向调起助手。
- **价值**：把助手嵌入既有开发动线，降低「切出来」的摩擦。
- **依赖与成本**：需要系统协议注册与严格的参数校验，成本中。
- **风险**：URI 协议可能被恶意链接滥用，必须校验参数、限定动作范围，避免变成本地提权入口。

#### EX-A-04 项目导入向导

- **说明**：从 VS Code / JetBrains 最近项目列表、常见代码根目录一键导入，替代逐个手动添加。
- **价值**：显著降低首次使用门槛和日常新增项目的成本。
- **依赖与成本**：只读读取编辑器配置，必须默认关闭并明确提示，成本低。
- **风险**：读取用户配置可能引发隐私顾虑，需在界面上说明用途。

#### EX-A-05 多窗口与分屏多项目

- **说明**：同时查看两个项目的任务进度与文件差异。
- **价值**：适合并行维护多个项目的开发者。
- **依赖与成本**：状态管理与 IPC 需支持多实例，成本中高。
- **风险**：过早引入会明显增加状态复杂度，建议在状态模型稳定后再做。

#### EX-A-06 剪贴板与截图快速建任务

- **说明**：将当前复制的报错信息、日志或截图直接作为任务上下文。
- **价值**：减少「复制—切窗口—粘贴」的重复动作。
- **依赖与成本**：剪贴板读取必须由用户主动触发，成本低。
- **风险**：剪贴板内容可能含敏感信息，禁止后台自动采集。

### 13.5 AI 协作深化

#### EX-B-01 Agent 工作树并行编排

- **说明**：多个任务在独立 Git worktree 中并行执行，互不干扰，最后统一审查。
- **价值**：把串行等待变为并行推进，提升批量任务吞吐。
- **依赖与成本**：需要 worktree 生命周期管理、任务隔离与清理策略，成本高。
- **风险**：磁盘占用、分支与工作树泄漏，以及清理失败后的残留；必须提供可见的清理与回收入口。

#### EX-B-02 任务检查点与一键回滚

- **说明**：任务执行前自动建立快照，允许整任务回滚。
- **价值**：降低尝试高风险改动的心理成本，提升用户让 AI 介入的意愿。
- **依赖与成本**：依赖 Git stash/commit 或文件快照机制，成本中。
- **风险**：对非 Git 项目、大文件与已提交改动的处理边界需要明确说明。

#### EX-B-03 结构化产物

- **说明**：让任务直接产出可落地的制品：TODO 清单（可勾选回写）、提交信息、PR 描述、ADR、变更摘要。
- **价值**：把 AI 输出从「一段回复」变成「可直接使用的工作产物」。
- **依赖与成本**：主要依赖提示词模板与写回策略，成本低。
- **风险**：写回文件属于高风险操作，必须走审批与差异确认。

#### EX-B-04 提示词库与模板版本化

- **说明**：可复用、可分享、可对比版本的提示词资产，比单一「任务收藏」更完整。
- **价值**：沉淀个人与团队经验，减少重复描述任务的开销。
- **依赖与成本**：本地存储加导出格式，成本低。
- **风险**：模板会随模型变化而过期，需标注适用模型与最后验证时间。

#### EX-B-05 用量与成本看板

- **说明**：按项目和任务统计 token 用量、耗时与费用估算。
- **价值**：让成本可见，支持用户主动控制开销。
- **依赖与成本**：网关需暴露用量字段，成本低到中。
- **风险**：协议字段可能变化，需容错与降级展示。

#### EX-B-06 本地与离线模型回退

- **说明**：网络不可用或项目敏感时，切换到本地模型（如 Ollama）。
- **价值**：保证离线可用性，并让敏感项目的数据不出本机。
- **依赖与成本**：需要统一的模型适配层，成本高。
- **风险**：能力差异可能导致用户预期错位，界面必须明确标注当前使用的模型。

#### EX-B-07 任务重放与时间线

- **说明**：以时间线回放一次任务的事件、审批与文件变化。
- **价值**：便于复盘、交接与问题定位。
- **依赖与成本**：需要稳定的事件持久化格式，成本中。
- **风险**：日志体积增长与敏感信息脱敏。

### 13.6 工程洞察

> 本组以只读为主，安全风险低，容易形成可见价值。

#### EX-C-01 依赖与安全扫描

- **说明**：调用 `npm audit`、`dotnet list package --vulnerable`、`pip-audit` 等命令，汇总已知漏洞。
- **价值**：把安全检查前置到日常开发，无需离开应用。
- **依赖与成本**：需要各生态命令适配，成本中。
- **风险**：命令版本差异与网络依赖，需支持离线降级与超时。

#### EX-C-02 变更影响面与热点文件

- **说明**：基于 churn、最近改动与调用关系，提示「改动这里可能影响哪里」。
- **价值**：降低回归风险，辅助任务范围界定。
- **依赖与成本**：主要依赖 Git 历史统计，成本中。
- **风险**：缺少静态分析时结论并不精确，必须标注置信度而非给出确定结论。

#### EX-C-03 项目指标看板

- **说明**：展示代码量、提交频率、分支活跃度、未完成 TODO 数量等。
- **价值**：为项目健康度提供直观信号。
- **依赖与成本**：Git 加文件扫描，成本低到中。
- **风险**：大仓库全量扫描的性能，需要增量与缓存策略。

#### EX-C-04 文档与图表自动生成

- **说明**：从代码结构生成 README 骨架、CHANGELOG 与架构图（Mermaid）。
- **价值**：降低文档维护成本。
- **依赖与成本**：复用 AI 任务模板即可，成本低。
- **风险**：生成结果必须人工确认，禁止默认覆盖既有文档。

#### EX-C-05 TODO 与 FIXME 盘点

- **说明**：汇总技术债清单，并可一键转为任务。
- **价值**：把散落在注释里的待办变成可执行任务。
- **依赖与成本**：文件搜索即可，成本低。
- **风险**：必须排除依赖目录与构建产物，避免噪声。

### 13.7 运行与隔离

#### EX-D-01 沙箱与容器化执行

- **说明**：高风险命令在容器或受限环境中执行。
- **价值**：在不牺牲便利的前提下提高操作安全性。
- **依赖与成本**：需检测容器运行时可用性，成本高。
- **风险**：环境差异可能导致结果不可复现，必须明确标注执行环境。

#### EX-D-02 SDK 与运行时版本管理

- **说明**：检测并切换 Node、.NET、Python 等版本（集成 nvm、volta、pyenv）。
- **价值**：解决「项目要求版本与本机不符」这类高频痛点。
- **依赖与成本**：需要外部工具检测与调用适配，成本中。
- **风险**：修改全局环境属于高风险，必须强确认并保留回退路径。

#### EX-D-03 大仓库性能策略

- **说明**：提供 sparse checkout、浅克隆、按需索引等选项。
- **价值**：让超大仓库仍可流畅使用。
- **依赖与成本**：需要 Git 能力检测与版本兼容处理，成本中。
- **风险**：会改变用户仓库状态的选项必须默认关闭。

#### EX-D-04 服务与端口面板

- **说明**：展示本机正在监听的开发端口，并支持关闭占用进程。
- **价值**：直接解决「端口被占用」这类高频阻塞问题。
- **依赖与成本**：解析系统命令（`netstat`、`lsof`）输出，成本低到中。
- **风险**：结束进程属于高风险操作，必须展示进程详情并等待确认。

### 13.8 外部系统集成

#### EX-E-01 Issue 与 PR 集成

- **说明**：从 GitHub/GitLab issue 直接生成任务，任务完成后回写 PR 描述。
- **价值**：打通「需求—实现—评审」链路。
- **依赖与成本**：需要 Token 存储（走系统凭据库）与网络调用，成本中高。
- **风险**：凭据安全，以及「默认外发」的隐私边界；外发必须显式触发。

#### EX-E-02 CI 流水线状态

- **说明**：在项目摘要中显示最近一次构建与测试状态。
- **价值**：一眼掌握项目可用性。
- **依赖与成本**：对接 CI 平台 API 或本地 CLI，成本中。
- **风险**：网络不可用时的降级展示与陈旧数据标注。

#### EX-E-03 通知中心与桌面提醒

- **说明**：任务完成、审批待处理、任务失败时发出系统通知。
- **价值**：解决「长任务期间不敢离开」的焦虑。
- **依赖与成本**：系统通知 API，成本低。
- **风险**：通知频率需要控制，避免打扰。

#### EX-E-04 工时与交付报告

- **说明**：面向自由职业与外包场景，按项目与任务汇总工时并导出报告。
- **价值**：把开发记录直接转化为可交付凭据。
- **依赖与成本**：基于任务历史统计，成本中。
- **风险**：涉及商业数据，必须本地存储并控制导出范围。

### 13.9 平台与治理

#### EX-F-01 插件市场与治理

- **说明**：在 13.2.G 技能系统之上补齐签名校验、审核流程、评分举报、下架撤回与兼容性矩阵。
- **价值**：让扩展生态可持续且可控。
- **依赖与成本**：需先稳定技能规范，成本高。
- **风险**：过早开放无审核市场会带来安全与维护负担。

#### EX-F-02 技能权限声明与沙箱

- **说明**：技能必须声明所需权限（文件读写范围、命令执行、网络访问），运行前展示给用户。
- **价值**：让权限边界对用户可见。
- **依赖与成本**：依赖既有策略模块，成本中。
- **风险**：无沙箱时权限声明仅具提示意义，容易被绕过。

#### EX-F-03 隐私面板与遥测开关

- **说明**：在一处看清并控制「采集了什么、存在哪里、如何删除」。
- **价值**：把隐私承诺变成可验证的用户控制项。
- **依赖与成本**：需要收敛埋点，成本低。
- **风险**：低；但需与第 8 章的安全原则保持一致。

#### EX-F-04 备份、导出与迁移

- **说明**：本地数据库一键备份与恢复，支持跨设备迁移（不含项目文件）。
- **价值**：降低数据丢失风险，便于更换设备。
- **依赖与成本**：需数据模型先稳定，成本低到中。
- **风险**：备份可能包含路径等敏感元数据，应提供加密选项。

#### EX-F-05 无障碍与多语言

- **说明**：键盘全流程可达、屏幕阅读器兼容、中英文界面。
- **价值**：扩大可用人群，并提升键盘重度用户的效率。
- **依赖与成本**：需设计规范先行，成本中。
- **风险**：后期补做成本远高于早期纳入。

## 14. 建议的拓展路线

### 第一批：提升单机效率

优先考虑：

1. 项目健康检查；
2. 内置终端和运行配置；
3. 任务历史与会话续接；
4. 文件语义搜索（第 4.9 节），支持不依赖准确关键词的本地代码/文档检索；
5. 任务规划模式和只读分析模式；
6. 数据导出与本地备份；
7. 自动感知、工作痕迹记录与工作树（第 4.8 节）。

这些功能直接服务于单机工作效率；新增工作树和语义搜索需要独立验证事件归类、索引质量和后台资源占用。

两个新增模块在第 9 节阶段 5 桌面端稳定后优先推进，先于移动端扩展，实施顺序如下：

1. 明确采集/搜索目录、排除规则和留存设置，准备事件与检索验收样例；
2. 实现项目事件采集、去重、持久化和工作树基础视图，再加入自动归类、用户纠正和回顾续接；
3. 独立实现文件解析、增量索引、本地向量与混合检索，保留关键词搜索降级；
4. 完成工作树与搜索结果关联，按第 11.5 节分别验收两个模块后开放。

两条实现线可在公共目录边界和存储契约明确后并行推进；先覆盖应用内活动和文本文件，再根据反馈扩展外部工具感知与文档格式。

### 第二批：形成开发工作台

可进一步加入：

1. 测试运行与失败分析；
2. Git 提交和代码评审辅助；
3. 插件/技能系统；
4. 自动化触发器；
5. 项目模板、标签和团队规范。

这些功能需要更完善的权限模型、任务模型和扩展接口。

### 第三批：跨设备与协作

最后评估：

1. 账号和设备管理；
2. 项目元数据与任务状态同步；
3. 移动端只读查看；
4. 远程审批和任务控制；
5. 团队协作与云端知识库。

此阶段的核心原则是“先可观察，再可交互，最后才允许高风险控制”。

### 补充拓展的优先批次（对应 13.4-13.9）

评估维度：用户价值、实现成本、与首版架构的耦合度。

**第一批：低成本、直接提升核心体验**

| 拓展 | 编号 | 价值 | 成本 | 理由 |
| --- | --- | --- | --- | --- |
| 命令面板 | EX-A-01 | 高 | 低 | 复用现有索引与技能注册表，串起所有入口。 |
| 通知中心 | EX-E-03 | 高 | 低 | 解决长任务期间的用户焦虑，改动局限在界面层。 |
| 结构化产物 | EX-B-03 | 高 | 低 | 只需提示词模板，无新增基础设施。 |
| 提示词库 | EX-B-04 | 中 | 低 | 数据量小，可先本地后共享。 |
| 依赖与安全扫描 | EX-C-01 | 中 | 中 | 只读命令，安全风险低，容易做出可见价值。 |

全局唤起与托盘常驻（EX-A-02）已纳入首版 P0，不在上述拓展批次重复排期。

**第二批：需先补齐基础设施**

- 任务检查点与一键回滚（EX-B-02）；
- IDE 集成与自定义 URI 协议（EX-A-03）；
- 变更影响面与热点文件（EX-C-02）；
- 项目指标看板（EX-C-03）；
- 技能权限声明与沙箱（EX-F-02）；
- 备份、导出与迁移（EX-F-04）。

**第三批：高成本或高风险，待权限与治理体系成熟**

- Agent 工作树并行编排（EX-B-01）；
- 沙箱与容器化执行（EX-D-01）；
- 插件市场与治理（EX-F-01）；
- Issue 与 PR 集成（EX-E-01）；
- SDK 与运行时版本管理（EX-D-02）；
- 面向外部系统的双向写回能力。

**建议明确延后或不做**（与 2.3、8.2 保持一致，防止范围蔓延）

- 跨设备同步项目文件、默认上传云端；
- 未经确认的远程命令执行与远程写文件；
- 全盘自动扫描并建立完整项目库；
- 在个人桌面版稳定前引入账号、组织与团队权限体系；
- 早期开放无审核的插件市场；
- 为追求指标而降低审批强度或隐藏错误（呼应第 15 章结尾原则）。

## 15. 产品度量建议

首版上线后可关注以下指标：

- 用户从启动到找到目标项目的平均时间；
- 项目搜索成功率；
- Codex 任务启动成功率；
- 任务状态和审批事件是否完整展示；
- 用户查看差异后的后续操作比例；
- 任务失败原因分布；
- 应用异常退出率；
- 高风险操作审批覆盖率；
- 用户主动使用项目健康检查、任务历史和搜索功能的比例。

指标用于发现产品问题，不应通过降低安全确认或隐藏错误来追求表面完成率。

## 17. 结论

本项目应以桌面端核心闭环为第一优先级，先解决“找到项目—调用 Codex—查看过程—审核结果”这一真实且高频的使用链路。技术实现上采用本地优先和模块化设计，避免过早引入跨设备同步、团队协作和远程高风险控制所带来的复杂度。

在首版稳定后，优先拓展项目健康检查、任务历史、自动感知工作树、文件语义搜索、测试运行和可控自动化；待权限、身份和审计体系成熟后，再逐步开放安卓端、跨设备同步和远程控制能力。

## 20. 阶段 0 分步实施方案

> 本节将第 9 章的“阶段 0：方案确认与技术验证”拆解为可逐步执行、逐步验收的工作包。阶段 0 以降低架构和外部依赖的不确定性为目标，不追求提前实现首版功能。除验证所必需的临时原型外，不在本阶段建设完整 UI、项目索引或可发布应用。

### 20.1 阶段 0 目标与边界

**目标**：在正式开发前验证桌面技术栈、Codex 本机集成可行性、系统能力调用方式、数据存储方向和基本安全边界，并形成足以启动阶段一的工程基线。

**阶段 0 完成定义**：

- 目标开发环境和工具链已记录，最小桌面工程能够在目标 Windows 环境启动；
- 已通过实际实验确认 Codex 通信入口、会话创建、消息发送、事件接收、取消和审批能力的可行性；
- 模型发现、思考强度参数、独立进程加载与隔离站点/Key 切换已有实测结论；cc-switch 自动接入由用户确认的手动管理替代方案退出范围，生产自管实现风险登记到对应功能上线门；
- 文件管理器、默认浏览器及 Git CLI 的验证结论明确，失败情况和限制有记录；
- SQLite 数据模型初稿、迁移策略、IPC 边界、安全约束和日志约定已形成文档；
- 所有阻断阶段一的风险均已关闭，或有经确认的替代方案和明确负责人；
- 阶段一的工程结构、首批任务和验收条件可以据此确定。

**本阶段不做**：完整产品界面、全盘项目扫描、完整 Codex 对话产品、Git 写操作、远程访问、账号体系、自动更新和发布签名。

### 20.2 分步工作包

#### 步骤 0.1：锁定验证基线

**工作内容**：

- 确认本阶段的目标操作系统与最低版本、目标 CPU 架构，以及首个可运行环境；默认先以当前 Windows 桌面环境为验证对象；
- 记录可用的 Node.js、包管理器、Rust、Tauri 2 所需系统依赖、Git 和 Codex 客户端版本；
- 确认本机 Codex 客户端是否已安装、是否可启动，以及用户当前可用的认证状态；只记录能力和版本，不采集或写入凭据；
- 记录应用自管与用户共享 Codex 配置的边界；既有 cc-switch 安装/版本调查保留为历史，不作为运行依赖；只记录认证类型/状态，不收集真实 Key；
- 建立阶段 0 决策记录和风险清单，对每项实验预先写清成功标准、失败后的下一步及是否属于阶段一阻断项。

**产物**：环境基线表、实验清单、风险登记册初稿。

**验收门槛**：开发环境可复现；验证范围和目标用户环境不存在未声明的假设。若目标环境尚未确定，先标记为待决策，不以本机成功推断所有 Windows 环境均兼容。

#### 步骤 0.2：验证 Tauri 桌面工程骨架

**工作内容**：

- 创建最小 Tauri 2 + React + TypeScript + Rust 工程；
- 完成开发模式启动、前端构建和 Rust 命令调用前后端往返；
- 验证窗口关闭、应用退出和基本错误输出；
- 记录开发命令、必要依赖、生成目录和干净环境下的复现步骤。

**产物**：可重复启动的最小工程、初始化说明、工具链问题记录。

**验收门槛**：在约定环境中可从仓库状态按文档启动应用，并成功完成至少一次前端到 Rust 再返回的调用。此处只验证框架链路，不建设正式导航和业务页面。

#### 步骤 0.3：验证 Codex 本机通信与任务生命周期

**工作内容**：

- 优先调查并验证第 7.2 节所述本机 app-server 通信入口；若不可用，再比较有官方支持依据的 SDK 或其他本机通信方式；
- 用最小客户端验证启动或连接、初始化/能力协商、创建会话、发送一条无文件修改的测试消息、接收增量事件和取得结束状态；
- 验证取消路径及其最终状态；
- 如协议提供审批请求，用隔离的临时项目和低风险测试验证审批事件的字段、批准/拒绝响应及拒绝后的状态；不得为验证而默认批准高风险操作；
- 验证工作目录能绑定到指定临时项目，并确认实际进程工作目录和协议上下文符合预期；
- 记录协议版本、消息/事件样例（移除敏感内容）、超时与进程退出行为、断连后的恢复限制，以及客户端未安装或未认证时的用户可见错误。
- 验证可用模型和支持的思考强度如何发现、传入任务及核对实际生效值；模型切换后重新校验强度选项；
- 确认 cc-switch 仅外部手动管理，应用 profile/Key 手动独立录入；桌面版、社区 CLI、导入链接和内部接口不纳入生产自动配置链路；
- 在隔离环境验证受控非官方站点的切换、Key 绑定、配置备份/失败恢复，检查凭据存储保护；官方源仅作预留，无需实测且结果不纳入通过判定；
- 验证自有独立 home 的加载时机、任务快照与自有进程重启策略；生产环境覆盖清理、项目配置及共享可变代理拒绝由 R-014/AT-AI-005/008 在功能上线前验证，不以隔离实验推断共享代理安全。

**产物**：Codex 集成验证记录、最小事件模型、模型/思考强度能力契约、自管配置及外部手动管理边界 ADR、历史 cc-switch 调查与未覆盖能力清单。

**验收门槛**：至少有一条可复现的“连接/启动—会话—发送—增量接收—完成”链路；取消、审批和认证能力逐项给出实测结论。若关键链路不可行，先决定并记录替代方案，不进入阶段一的 Codex 相关接口固化。

新增 AI 配置门槛：非官方源真实通信/认证、模型与思考强度参数，以及隔离合成站点的 provider/Key 切换、加载时机和失败保留分别有证据。cc-switch 自动接口不再是门槛；应用自管生产凭据库、环境/项目覆盖隔离和完整恢复仍须在相关功能上线前实测，不得将受控模拟或范围调整写成真实服务/完整产品通过。官方源仅作预留，不实测且不纳入通过判定。

#### 步骤 0.4：验证 Git 与系统打开能力

**工作内容**：

- 在临时 Git 仓库和非 Git 目录分别验证 Git 可用性检测、当前分支、工作区状态及结构化差异输出；
- 验证 Git 未安装、目录不是仓库、命令超时和非零退出码时的识别方式；
- 验证通过系统能力打开指定目录、文件和编码后的搜索 URL；
- 检查路径包含空格、非 ASCII 字符和特殊字符时的行为；验证失败不能导致 Shell 字符串拼接或命令注入。

**产物**：Git/系统集成验证表、建议命令与参数、错误分类和平台限制。

**验收门槛**：只读 Git 信息和系统打开能力有明确、可复现的调用方式；失败场景可区分并能返回可理解的错误。若某项能力依赖平台插件或权限配置，应记录为阶段一前置条件。

#### 步骤 0.5：敲定数据与迁移初稿

**工作内容**：

- 按首版核心闭环梳理 projects、project_usage、sessions、tasks、approvals、settings、audit_events 的最小字段、主外键和索引；
- 补充 provider_profiles、model_capabilities、ai_config_snapshots，以及全局/项目默认值、站点 Key 引用与任务快照关系；
- 区分必须持久化的数据、可重建缓存和明确不保存的数据；
- 验证 SQLite 在应用数据目录中的创建、读写、事务和重启持久化；
- 选定迁移版本管理方式，并定义迁移失败时的备份、报错和恢复原则；暂不实现完整业务仓储层。

**产物**：ER 图或表定义初稿、数据留存说明、迁移 ADR。

**验收门槛**：首版核心实体及其关系没有关键歧义；敏感凭据不进入普通数据库或日志；数据库升级失败不会静默覆盖或删除用户数据。

#### 步骤 0.6：确定 IPC、错误、日志与安全约定

**工作内容**：

- 划定 React、Rust 服务层和外部进程适配器之间的职责；列出阶段一所需的最小命令、事件及类型版本策略；
- 将 provider 列表、模型能力、脱敏 Key 状态、连接测试、切换等待和回滚结果纳入 IPC 契约；完整 Key 的输入只流向凭据服务，不作为普通 IPC 返回值；
- 统一错误分类、错误码前缀、用户提示、可执行建议和日志关联 ID；
- 约定日志脱敏、保留范围、轮转/清理方式，禁止记录令牌、密码、完整敏感提示词和不必要的文件内容；
- 明确路径规范化与访问边界、外部进程参数数组调用、超时/取消、审批默认策略和审计最小字段；
- 将可测试的威胁用例列入清单，至少覆盖路径穿越、命令注入、审批绕过和敏感信息泄露。

**产物**：IPC 契约草案、错误与日志规范、安全检查清单及对应测试用例。

**验收门槛**：阶段一团队能够据此实现第一个服务命令而无需自行猜测权限、错误和日志口径；高风险操作默认不会绕过用户确认。

#### 步骤 0.7：汇总决策并通过阶段门

**工作内容**：

- 汇总所有实验的实际结果、环境限制、未验证假设和证据位置；
- 对 Tauri 工程、Codex 通信、SQLite、Git 调用和系统打开能力逐项作出“采用 / 有条件采用 / 替代 / 暂缓”决策；
- 评估未关闭风险对阶段一的影响，明确缓解措施、负责人和复审节点；
- 将阶段一拆为可估算的首批任务，补充每项任务的完成定义和最小测试。

**产物**：阶段 0 总结、决策记录（ADR）、风险清单定稿、阶段一启动清单。

**验收门槛**：不存在未决的阶段一阻断项；关键外部依赖都有已验证方案或明确替代方案；阶段一能够在不改变阶段 0 核心决策的前提下启动。未达门槛时只继续处理阻断项，不以“原型能启动”视为阶段 0 完成。

### 20.3 建议执行顺序与依赖

建议严格按以下顺序推进：

1. 步骤 0.1 锁定验证基线；
2. 步骤 0.2 建立桌面工程骨架；
3. 步骤 0.3 验证 Codex 通信（若需先做协议调查，可在骨架创建期间并行调查，但最终以本机实测为准）；
4. 步骤 0.4 验证 Git 与系统打开能力；
5. 步骤 0.5 形成数据和迁移初稿；
6. 步骤 0.6 固化 IPC、错误、日志和安全约定；
7. 步骤 0.7 评审阶段门并决定是否进入阶段一。

步骤 0.1、0.2 的基础工作完成前，不应大规模编写业务代码。Codex 通信属于核心风险，应尽早验证；若其验证失败，应优先解决集成路线，而不是先构建依赖该路线的 UI。

## 21. 阶段 1 分步实施方案

> 本节承接第 9 章“阶段 1：桌面端基础”，将 docs/phase-0/phase-gate-review.md 中的 S1 任务细化为实施步骤。编号映射见 21.3；既有 S1 编号保持不变，后续实现、提交和验收可同时引用步骤号与任务 ID。本次仅补充实施计划，不表示业务功能已经完成。

### 21.1 目标、前置条件与范围

**目标**：将阶段 0 验证骨架建设为具备正式导航、常驻悬浮入口、设置持久化、类型化本地服务、错误恢复和自管 AI 配置基础的桌面应用，为阶段 2 项目管理及阶段 3 Codex 工作流提供可复用服务。

**启动依据与实施基线**：

- 阶段 0 已按 ADR-0011 的“用户手动管理 cc-switch、应用自管 profile”替代范围通过，S1-00 已完成；从步骤 1.1 开始实施，无需重新启动自动集成调查。
- 首轮验收沿用阶段 0 的 Windows 11 build 26300 x64 和已锁定工具链，具体版本见 docs/phase-0/environment.md；新系统、架构或协议版本需单独验证。
- IPC、数据、迁移和安全实现分别遵循 docs/phase-0/ipc-contract.md、data-model.md、storage-migration-adr.md、errors-and-logging.md、security-checklist.md。
- 当前 framework_probe、实验脚本、SQLite probe 和参考 guard 是复用起点；正式启动、业务仓储、命令授权、凭据服务与隔离必须另有生产实现证据。

**阶段 1 交付范围**：主窗口与导航、独立悬浮球/输入面板、全局快捷键、托盘启停、窗口生命周期与位置恢复、全局设置、正式数据库生命周期、严格 IPC、错误提示、运行日志与最小审计、系统凭据库、自管 profile/模型能力/默认选择及 AI 配置页。项目级设置先建立类型和已登记项目校验边界，实际项目入口随阶段 2 接入。

**与后续阶段的衔接**：阶段 1 的 Codex 适配仅满足配置探测、连接测试、进程隔离和切换恢复；任务快照建立生成与不可变存储能力，使用合成任务验证。悬浮输入面板在阶段 1 验证窗口与输入基础，真实发送/取消按钮保持明确不可用；项目上下文阶段 2 接入，正式对话与悬浮入口任务发送、事件反馈、审批提示在阶段 3 接入。任意项目路径打开、Git 与网络搜索、审批执行和文件差异仍按阶段 2–4 的既定依赖实施。自动感知工作树、文件语义搜索沿用第 14 章拓展安排，不在本阶段创建相关业务表或索引。

官方源仅作预留，沿用本文当前执行约定。真实 Key 输入/持久化/使用须先通过凭据与安全验收，网络测试须再通过隔离验收；未达功能门时保留明确不可用提示，不用实验结果替代生产通过。

### 21.2 分步工作包

#### 步骤 1.1：完成桌面主框架与导航（S1-01）

**前置条件**：阶段 0 阶段门通过；现有工程和工具链可复现。

**实施顺序**：

1. 整理 src/ 与 src-tauri/ 的现有入口，保留 src/ipc/ 为唯一前端服务调用入口；按需建立页面、公共组件、Rust 服务和适配器模块。
2. 建立主窗口布局、项目入口占位、设置入口与 AI 配置入口，明确初始页面和导航切换规则；暂未实现的功能显示当前状态。
3. 为启动中、空状态、服务不可用和错误恢复提供统一呈现；完成基础键盘导航、焦点和表单反馈。
4. 建立默认开启的独立 overlay window，复用窗口实现悬浮球/展开面板；接入普通窗口置顶、点击展开、输入聚焦、换行、草稿保留、收起、关闭及多显示器位置校正。本步骤先验证默认行为；1.4 接入后须先读回有效设置再决定是否创建/显示入口，避免已停用状态在启动时短暂开启。
5. 接入可配置全局快捷键与托盘菜单；快捷键冲突显示修复入口，托盘提供展开对话、启停常驻、打开主窗口和退出应用。依照第 4.2 节实现主窗口关闭、停用入口与明确退出的区别，避免重复创建窗口或遗留监听器。
6. 将阶段 0 probe/测试模式与正常业务启动分开；隔离验证入口沿用原关闭退出语义，避免正常启动执行实验或访问外部配置。业务面板在真实任务服务未接入时显示不可用状态，不以测试输入代表真实发送。

**交付物**：桌面主框架、导航与页面壳层、悬浮球/输入面板、全局快捷键与托盘、窗口生命周期和位置恢复组件、模块职责说明、更新后的启动说明。

**最小验证与验收门槛**：前端构建与 Rust check 通过；开发模式和嵌入资源模式均能显示真实窗口、切换页面、显示启动错误；悬浮球置顶、展开聚焦、输入换行、收起/关闭、快捷键冲突、托盘恢复及明确退出可复现。位置和启用状态的持久化在 1.4 完成后补验；真实任务保留阶段 3 验收。阶段 0 的脚本仍可按原隔离入口运行。

#### 步骤 1.2：接通正式 IPC、状态与事件通路（S1-02）

**前置条件**：步骤 1.1；IPC v1 草案和错误规范可用。

**实施顺序**：

1. 对齐 TypeScript/Rust 请求、返回和事件类型；落实 apiVersion、严格字段校验、长度限制、服务端 correlationId 和固定错误 envelope。
2. 首先实现 app_get_status，返回各服务的已实现状态与不可用原因；cc-switch 只返回手动管理/集成关闭，不检测安装或版本。
3. 建立命令注册和最小窗口 capability；以后每个业务命令随对应步骤同时接入 DTO、权限、服务调用和失败映射，不提前授权空接口。
4. 实现统一事件监听/注销及序列校验；重复事件忽略，序列缺口或进程 streamId 变化后重新查询状态。异步操作落实超时、取消和状态查询契约，不自动重发变更请求。
5. 为 main 与 overlay 分别定义 capability，overlay 仅接入所需窗口控制、脱敏状态和设置开关；后续任务命令在阶段 3 随对应服务授权。活动上下文由服务层共享，使用合成状态验证两窗口同步、窗口重建和监听注销；不将全部主窗口权限复制给 overlay。

**交付物**：正式 IPC 调用封装、状态命令、事件基础、命令权限清单与错误通路。

**最小验证与验收门槛**：版本错误、未知字段、非法输入、未授权窗口/远端调用在副作用前被拒绝；真实 WebView2 可完成成功与失败往返；响应和日志不包含原始异常或 payload。事件重放、缺口和监听清理有可复现验证。

#### 步骤 1.3：接入正式数据库、仓储与启动恢复（S1-03）

**前置条件**：步骤 1.2；采用 schema v1 和 ADR-0008。

**实施顺序**：

1. 在正常启动中解析 app_data_dir、打开业务数据库、取得迁移写锁并执行迁移；失败进入可解释的受限状态，保留原库和备份。
2. 为本阶段实际使用的设置、profile、能力缓存、配置快照和审计建立类型化仓储与事务边界；后续项目/会话服务按需扩展，不暴露任意 SQL IPC。
3. 在启动事务中将未终态运行任务及 pending 审批标为 interrupted，记录最小恢复事实；不恢复执行、不重放审批，不由本地状态推断外部进程已结束。
4. 接入数据库 busy、权限、损坏、高版本和迁移失败的固定错误；提供按 ADR 的人工恢复说明。新增字段只追加迁移，禁止修改已发布 0001 或迁移校验和。

**交付物**：正式数据库初始化、业务仓储基础、启动恢复逻辑、迁移与人工恢复说明。

**最小验证与验收门槛**：独立进程重开能读回记录；写入和迁移失败保持原数据；未知/损坏/高版本库不会被静默重建；恢复事务重复运行不会重放任务或批准操作。

#### 步骤 1.4：完成全局设置读写与重启恢复（S1-03a）

**前置条件**：步骤 1.2、1.3。

**实施顺序**：

1. 实现 settings_get/settings_update，仅接受已约定的设置键和类型；初始化默认搜索引擎、排序、审批策略、日志级别和摘要留存期限，未配置 editor/AI 默认值保持未配置。
   常驻设置包括启用开关（首次默认 true）、快捷键（默认 Ctrl+Alt+Space）、悬浮位置及显示器标识；保存停用状态后，重启不得重新开启。收起状态不作为停用状态，重启统一先显示悬浮球而非展开面板。
2. 更新采用 expectedRevision 与单事务提交；非法值、修订冲突或写入失败拒绝整个批次，保留旧值。审批策略当前仅允许 ask；编辑器保存结构化标识/可执行路径。
3. 连接设置表单，区分读取、编辑、保存中、成功和失败；以服务返回值更新界面，冲突后先重读再由用户提交，不自动覆盖。
4. 启动时读回并校验持久化值，区分缺项使用默认与损坏值报错；项目级设置仅接受已登记、已授权项目，阶段 2 再接入实际项目入口。
5. 统一设置页与托盘的常驻开关写入路径及事件同步，快捷键注册失败提示更换；恢复位置按当前工作区/缩放校正，已移除显示器改用主显示器可见位置。失败不显示虚假的保存成功；未发送草稿不进入持久设置。

**交付物**：设置服务、可用设置页、并发修订规则和重启恢复流程。

**最小验证与验收门槛**：覆盖默认值、非法键/值、整批回滚、并发冲突和损坏设置；真实桌面明确退出重启后读回常驻开关、快捷键、位置和显示器，覆盖托盘/设置同步、注册冲突和显示器断开。设置不能存储 Key；设置摘要期限不自动开启摘要采集。

#### 步骤 1.5：落实错误呈现、日志、审计与清理（S1-04）

**前置条件**：步骤 1.2、1.3；设置页入口依赖步骤 1.4。

**实施顺序**：

1. 统一固定错误码、提示、建议和关联 ID 的展示；服务内部错误映射后返回，前端不输出原始异常对象。
2. 在 app_log_dir 实现白名单 JSON Lines 和单写者轮转：每行不超过 4 KiB、每文件不超过 5 MiB、最多 5 个文件、最多 7 天且总量不超过 25 MiB；磁盘/权限失败停止本次落盘并固定提示。
3. 实现最小审计仓储，让配置变更与相应审计事实在同一事务中提交；需要安全审计的高风险操作遇持久化失败拒绝执行。普通日志故障不阻塞取消和安全恢复。
4. 实现过期审计（默认 90 天）及本应用日志清理，核验目录身份并拒绝联接/符号链接越界；摘要默认关闭，验证脱敏后才允许开启。诊断先提供白名单状态汇总，导出如开放须有预览、确认和秘密检查。

**交付物**：统一错误组件、持久日志、轮转与清理服务、最小审计和状态诊断入口。

**最小验证与验收门槛**：注入磁盘满、权限不足、SQL 失败及超限；秘密哨兵不出现在 IPC、日志、审计、诊断或备份中；清理不删除项目、数据库、凭据或备份。审批原子决定与消费在阶段 3 接入前仍须另验。

#### 步骤 1.6：实现系统凭据库与安全引用（S1-05）

**前置条件**：步骤 1.2；凭据接入正式 profile 前完成步骤 1.3、1.5 的仓储与审计边界。

**实施顺序**：

1. 建立当前 Windows 环境的系统凭据库适配与应用命名空间；只保存应用自管 secret，设计 profile ID、凭据 revision 和规范化 origin 的绑定校验。
2. 接入 credential_put/remove 的专用权限；Key 输入只进入凭据服务，返回状态与版本，不提供读取 secret 的 IPC。普通库仅保存 credential:<profile_id>:<credential_revision> 逻辑引用。
3. 为替换/删除设计跨凭据库与 SQLite 的补偿流程：先核验修订和占用，再更新安全记录与元数据；中途失败保留原可用引用或标记不可用，不能留下“已保存”的假状态。
4. 凭据变更使关联连接测试与能力缓存失效；受影响自有任务占用时等待空闲。凭据库不可用或绑定失败时拒绝操作，不降级到文件、普通库或继承环境变量。

**交付物**：系统凭据适配器、引用解析服务、专用 IPC 和替换/移除补偿规则。

**最小验证与验收门槛**：使用本应用临时合成凭据验证写入、独立进程读回、替换、删除与清理；覆盖错误 origin、失效 revision、凭据库不可用和元数据提交失败。通过 R-016/AT-AI-007 对应检查后才开放真实 Key 输入和持久化。

#### 步骤 1.7：实现自有进程配置与实际路由隔离（S1-06）

**前置条件**：步骤 1.2、1.6；生产接入前通过步骤 1.5 的错误/日志检查。

**实施顺序**：

1. 将阶段 0 stdio 方案封装为 Rust 自有进程适配器，使用受控可执行路径、参数数组、cwd、专属 home 和环境允许列表，记录进程归属与退出状态。
2. 仅从应用 profile/凭据服务构造配置，阻止继承外部认证、provider 和代理覆盖；识别并拒绝未经核验的项目配置覆盖及共享可变路由。
3. 建立配置指纹、实际来源核验、超时与候选取消清理；只管理本应用子进程和临时 home，失败不终止其他客户端或改写用户共享配置。
4. 通过受控站点验证实际 endpoint、合成 Key、模型和强度；模拟外部 config/auth 改动、环境覆盖、项目覆盖、cc-switch 缺失/升级及共享路由接管，验证隔离或固定错误拒绝。

**交付物**：Rust 进程适配器、专属配置构造器、隔离拒绝策略和实际路由验证记录。

**最小验证与验收门槛**：AT-AI-005/008 的配置层隔离用例有实际请求证据，外部配置不变、自有资源清理通过；不能证明隔离时返回 PA_PROVIDER_SHARED_ROUTE_UNSAFE，不启动请求。真实任务并发场景在阶段 3 网关接入后再次验收；历史独立 home 实验不能替代本步骤。

#### 步骤 1.8：实现 profile、能力、默认选择与快照服务（S1-07）

**前置条件**：步骤 1.3、1.5、1.6、1.7。

**实施顺序**：

1. 接入 providers_list/provider_save/set_enabled/delete，完成名称、HTTPS endpoint/origin、协议和 revision 校验；服务只激活 self_managed/owned_process，有历史引用的 profile 优先停用，旧外部管理记录提示手动重建。
2. 接入 provider_models，提供受版本控制目录或隔离探测结果，记录来源、有效期和支持强度；模型缓存最长 24 小时，profile 修订/适配器版本变化立即失效。未验证组合不可选择。
3. 实现全局默认与一次性选择校验、provider_test/provider_switch、operation_get/cancel。列表读取不算 ready；测试主动发起，证据绑定完整 selection/revision，按 IPC 契约 5 分钟有效。队列 FIFO、最多 8 项；提交前在锁内重验修订并按需要等待受影响自有任务空闲。
4. 落实 checking → waiting_for_idle → applying → completed 及失败恢复：未变更为 unchanged，已恢复并核验为 rolled_back，恢复失败为 rollback_failed、active=null 并阻止新任务；只有核验通过才原子提交默认值和发布事件。
5. 建立不可变快照生成/仓储；按“本次选择 > 项目默认整组 > 全局默认整组”解析，不拼接不同源参数。以合成任务验证实际配置、凭据引用和修订固定；正式 task_start 在阶段 3 同事务接入，当前不开放对话任务入口。

**交付物**：profile/能力/默认选择服务、连接测试与切换状态机、恢复入口、快照服务。

**最小验证与验收门槛**：覆盖两站点合成 Key 绑定、跨站重定向拒绝、能力失效、并发修订、候选取消、等待空闲和三类恢复结果；快照不因默认值或 Key 变化而改写。AT-AI-001/003/004/006/007 的配置层用例通过；运行任务相关用例阶段 3 补验。

#### 步骤 1.9：完成 AI 配置页与选择流程（S1-08）

**前置条件**：步骤 1.1、1.2、1.8。

**实施顺序**：

1. 接入 profile 新增/编辑/启停/删除与凭据提交表单；Key 采用掩码输入，提交完成后清空，不缓存到浏览器存储，不回显完整值或末尾片段。
2. 展示服务源、模型、可用强度、默认选择及凭据状态/版本；切换模型重新校验强度，无效配置提示修复，不静默切换到另一站点。
3. 接入用户主动连接测试、设置默认、进度、等待空闲、取消和失败恢复；说明连接测试可能产生用量，区分保存元数据、测试通过和实际应用成功。
4. 展示 cc-switch 为外部手动管理的说明；重启从服务恢复已持久化状态并重新校验。预留后续任务输入区的选择组件，对话入口在阶段 3 接入。

**交付物**：可用 AI 配置页、复用选择组件、配置状态与恢复交互。

**最小验证与验收门槛**：真实桌面完成合成 profile 的创建、凭据提交、测试、默认选择、失败恢复和重启读回；按钮状态与 Rust 实际生效状态一致。非法组合、双重提交、修订冲突、失联后查询和 Key 不回显均有验证。

#### 步骤 1.10：完成阶段回归、证据归档与移交（S1-09）

**前置条件**：步骤 1.1–1.9；按功能门保留不可用能力时必须明确列出缺口。

**实施顺序**：

1. 汇总各步骤的完成状态、适用环境、命令/事件/迁移变更、证据和遗留风险；更新 README 的实际启动与验证方式。
2. 建立阶段 1 统一验收入口，组合构建、Rust/IPC/仓储/凭据/隔离验证与真实桌面回归；用隔离目录和合成数据执行，清理仅限本次自有工件。
3. 执行 21.5 的阶段验收用例，检查常驻启停、快捷键、普通窗口置顶、多显示器、关闭/退出/重建、数据库失败、日志降级、配置失效、恢复失败和秘密泄露；有外部用量的真实服务测试须明确范围并单独记录，官方源不纳入。
4. 形成阶段评审和阶段 2 移交清单，说明可复用服务、不可用能力和下一步项目权限需求；将悬浮入口真实任务发送/取消、上下文快照、任务审批、真实任务并发隔离等未接入场景交给阶段 3 功能门，不记为通过。

**交付物**：阶段 1 验收报告、可重复入口、脱敏证据、更新后的运行说明与阶段 2 移交清单；建议实现时写入 docs/phase-1/，临时报告写入 artifacts/phase-1/，目录随实际工作创建。

**最小验证与验收门槛**：所有纳入交付的能力有生产实现和本阶段证据；失败能恢复或保持受限状态，不能损坏数据、泄露 Key 或改变共享配置。任何安全/数据阻断项未关闭时不宣布阶段 1 全部完成。
