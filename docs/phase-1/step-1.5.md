# 步骤 1.5（S1-04）实施与验收记录

日期：2026-10-18（Asia/Shanghai）。实际实施：Codex（前后端、存储、安全边界与集中验证）。

状态：实现中；集中验证结果完成后更新。本记录仅针对 1.5；不表示 M1 或阶段 1 整体完成。

## 实现范围

- 前端 `ErrorNotice` 与本地固定错误目录统一显示错误码、提示、建议和关联 ID；未知错误固定映射，服务返回的自由文本及原始异常不进入界面。
- `app_log_dir` 下的 JSONL 持久日志只记录静态命令/事件、服务端关联 ID、固定结果与固定错误码。单行 4 KiB、单文件 5 MiB、当前加四个轮转文件、最多 7 天/25 MiB；单写者串行写入与清理，日志级别随成功设置提交应用。
- 启动保护失败、磁盘满、权限不足或目录身份检查失败停止本次日志落盘，以固定错误和服务状态提示；日志故障不取消正常设置、退出或安全恢复能力。
- 设置、托盘启停、快捷键和位置变更与最小审计同一 SQLite 事务。审计写入与过期清理先于运行时设置准备；拒绝审计时整批不提交，prepare 不执行。运行时已准备而数据库最终提交失败时仍恢复旧运行状态。
- 沿用 schema v2 的 `config_switch/success` 表示一次设置批次成功提交，不复制键值、坐标、显示器、编辑器路径或自由文本。命令 envelope、普通日志与对应审计使用同一关联 ID；已有迁移与校验和不变。
- 审计默认 90 天，启动和周期清理只删除过期 `audit_events`，不删除任务、审批、项目、数据库或备份。摘要采集保持关闭，保存留存期限不启动采集。
- 新增仅 main 可用的 `logs_get_status`、`logs_clear`，同步 Rust 注册、DTO、返回校验、构建命令表和 capability；Rust 再校验真实窗口及本地 URL。清理不接收路径或任意筛选参数。
- 设置页提供本应用日志清理，诊断页提供日志级别、启用状态、文件数/总字节、固定故障码和留存政策的白名单汇总。未开放日志/配置/数据库导出与审计手动删除。

## 边界与后续复审

- 磁盘满/权限故障采用受控 I/O 注入，不填满真实磁盘；记录时区与操作系统环境，不将注入标为物理磁盘故障实测。
- 1.5 只落实已开放设置服务的事务审计与失败拒绝。凭据、profile/切换和真实任务在各自阶段接入同一审计边界；审批决定与消费的原子性必须在阶段 3 另验。
- 未验证脱敏前不开放自由文本摘要；诊断导出如后续开放，仍须预览、确认和秘密检查。
- 实际托盘鼠标操作、物理显示器拔插和实时 DPI 变化仍由 1.10 人工复核，不因本次日志实现变为通过。
