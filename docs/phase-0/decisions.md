## ADR-0002：最小 Tauri 2 + React + TypeScript + Rust 骨架

状态：采用步骤 0.2，验收结论见 verification.md。

使用官方 create-tauri-app 的 react-ts 模板，在根目录保留 Rust 和前端分离结构；只保留一个 `framework_probe` 实验命令。成功返回文本、平台与架构，空输入返回 Rust 错误，UI 提供等待、错误和重试。正式 IPC 类型、服务分层和日志策略仍留到 0.6，本命令不作为产品业务接口。

移除模板的 Opener 插件及权限，系统打开留到 0.4。保留必要 core 权限并设置 CSP。关闭自动安装包生成，只验证开发与嵌入资源的调试程序；图标暂用模板资源，不作品牌决定。不建设正式导航、项目索引、Codex 会话、SQLite 或 Git 功能。

## ADR-0005：采用自有 stdio app-server 作为 Codex 集成路线

状态：采用阶段 0 通信实验，支持基线限定 CLI `0.162.0-alpha.17.2`、当前 Windows x64；步骤 0.3 当前按 ADR-0011 替代范围通过，生产服务与阶段一接口仍须实现后验收。

本机 CLI 提供 app-server 和协议类型导出；真实中转源已验证初始化、会话、无修改消息、增量事件、完成、取消及命令审批批准/拒绝。生命周期和双向审批均可取得，没有必要改用 SDK。官方网页本轮 403 不影响本机 schema/实测证据，调查 main 源码不作为版本保证。

选择自有子进程、独立 cwd/home，可限定超时、退出和重启归属；不为 provider 切换停止用户其他任务或共享 daemon。支持配置绝对 CLI 路径与动态发现，未硬编码安装 hash。阶段 0 先用 Node 实验；正式 Rust 适配器留到阶段一，React 不依赖 wire 字段，0.6 固化 IPC。

完成以 turn/completed 为准，interrupted 映射 cancelled；操作审批拒绝不直接等于任务 failed，未知审批默认拒绝。请求和事件分别超时，断连不自动重发，ephemeral 重启后需新建会话。Alpha 协议升级需重导出类型并复验。持久恢复、文件和其他审批类别仍未验证。证据：codex-verification.md、codex-contract.md、本机 artifacts/codex-real/report.json。

## ADR-0006：固定 provider 快照，cc-switch 自动接口暂缓

状态：历史有条件采用；2026-10-11 已由 ADR-0011 替代自动接入范围。以下保留原评审与实验结论，不再要求用户切回 cc-switch。

真实 CLI + 合成 A/B 服务证明任务保持运行时源、HTTP 模型/强度匹配选择、各站点使用自己的 Key；401 候选失败不破坏原配置，A → B → A 可恢复。旧进程的新会话可读取新配置，不能假设所有配置只在启动读取。仍选择候选独立测试、等待自有任务空闲、固定快照、重启自有进程、新建会话；全局代理对外部任务影响未验证。

快照保存 profile ID、endpoint、模型、强度、凭据引用；发送前校验 Key 的 profile ID 和 origin。生产凭据由系统凭据库解析，不进入普通数据库或任务记录。阶段 0 只实现冻结元数据/验证契约和受保护临时实验，未实现完整凭据库。

cc-switch 桌面 4.0.6 的内部 Tauri provider 命令不是外部 API；深链只提供导入/UI 确认，社区 CLI 独立发布且未验证。普通 SQLite 文件头与 JSON 存储源码不能提供“Key 已加密”保证。禁止依赖内部表或注入该应用 WebView。等受支持外部接口明确后再验证隔离切换；若改为手动管理加应用自管 profile，必须明确调整自动集成验收，不能按原要求宣称通过。

官方认证和官方 ↔ 真实中转站往返未验证；按当前执行约定，官方源相关功能仅作预留，无需实际测试，其测试结果不纳入测试、阶段验收或发布的通过判定。步骤 0.3 仍因 cc-switch 自动接口及共享路由缺口跟踪为阻塞；官方源不构成阻塞，也不记为实测通过。证据：cc-switch-verification.md、codex-verification.md。

2026-10-10 配置修复后的补验采用一次性只读诊断核对 cc-switch 导出的连接，再在受限临时 home 中执行非官方实验。站点/凭据必须一致；模型默认值差异单独报告并校验实时模型。新增真实实验官方源拒测保护，保留 ADR-0006 的自动接口阻塞判断，不调整 FR-AI-006 验收。详见 cc-switch-retest.md。

2026-10-11 复审：上游推荐的社区 CLI 5.11.0 已以便携包完成九项隔离检查。列表/添加/current/切换和备份/导出可用；编辑/导入/恢复需要交互终端，Windows 缺少 `start`/daemon，尚不能作为完整外部自动契约。用户桌面库只读 PRAGMA 与 CLI 新库均为 schema 20，不将版本相同视为兼容保证，不把 CLI 接到共享库。继续等待受支持桥接契约和独立桌面实例验证，保留自动集成阻塞及原验收要求；负责人仍为集成负责人。证据、复现、清理与剩余门槛见 cc-switch-cli-verification.md。

## ADR-0007：Git 只读 CLI 与受限 Tauri Opener

状态：采用步骤 0.4 的 Windows x64 验证路线；正式项目权限和跨平台适配留到阶段一。

Git 以系统 `git.exe` 为首版只读信息来源。进程必须使用可执行文件加参数数组、指定工作目录、超时和退出码，不拼接 Shell 命令。仓库探测先于状态查询；状态用 porcelain v2 `-z`，差异元数据用 `--raw -z`，暂存与未暂存分别查询。临时仓库的分支、修改、重命名、未跟踪文件及特殊路径实测通过；缺失 Git、非仓库、超时与非零退出也可区分。阶段 0 Node 脚本只是调用/解析实验，正式 Rust 服务接口由后续阶段实现。

系统打开采用 Tauri Opener 2.7.0。阶段 0 只允许 `$TEMP/phase-0-system-open/**` 路径和 `http://127.0.0.1:*/*` URL；真实 WebView2 已调用系统打开目录和文件，默认浏览器对编码后的本机搜索 URL 发起请求。插件原样调用缺失路径在本机曾返回 Windows 取消码 1223，因此增加夹具范围内的 Rust 预检查，给出明确缺失/越界错误；插件的独立越界拒绝也已实测。该预检查不作为任意项目路径的最终安全边界。

阶段一开放项目目录前需设计按项目授权的 scope、规范化与重解析点处理；开放网络搜索前需确定 HTTPS 站点范围并复验。其他 Windows 版本、ARM64、macOS/Linux 和默认关联异常未验证。证据与建议命令见 git-system-verification.md；阶段 0 整体仍受 0.3、0.5–0.7 的结论约束。

## ADR-0008：Rust SQLite、版本化事务迁移与升级前备份

状态：采用步骤 0.5 初稿，2026-10-11；当前 Windows x64 实测通过。

使用 rusqlite bundled/backup，将普通元数据保存在 Tauri 应用数据目录；十个核心实体与迁移账本的 STRICT SQL 定义已形成。凭据只存绑定 profile/revision 的逻辑引用，任务绑定不可变快照；项目/全局默认值分作用域唯一，模型能力可重建。通过 user_version + LF 规范化 SHA-256 迁移账本管理版本，发布后只追加 SQL。写锁中先做含 WAL 的一致性备份，所有升级与版本更新同事务，失败保留原库；高版本、损坏和历史不一致拒绝重建。完整选型、失败码、手动恢复原则及未实现范围见 [迁移 ADR](storage-migration-adr.md)，字段与留存见 [数据模型](data-model.md)，实测见 [SQLite 验收](storage-verification.md)。

## ADR-0009：应用 IPC v1、固定错误和白名单日志，风险操作默认确认

状态：采用步骤0.6契约与参考验证，2026-10-11；正式业务服务按后续功能实现，不扩大0.3外部集成结论。

React仅通过类型化客户端访问Rust服务，外部协议/配置/进程留适配器。应用API主版本独立于数据库与CLI协议；严格请求、互斥成功/错误envelope、服务端关联ID、固定PA模块错误码与可执行建议成为第一服务命令基线。事件有streamId/sequence及查询恢复，receipt不表示成功，取消等待终态。provider/revision/模型/Key状态、候选测试、等待空闲、unchanged/rolled_back/rollback_failed、外部变更已纳入DTO，完整Key只入凭据服务，UI返回不含Key或凭据引用。cc-switch不支持时明确不可用，不能偷偷改内部表。

普通日志采用固定字段白名单而非任意payload加正则；默认info，阶段一限7天/25MiB，审计90天，诊断不复制原配置/数据库。当前只实现probe JSON stderr，不部署轮转/清理。高风险操作默认ask、未知审批deny；审批须绑定精确操作、任务、窗口和期限且单次消费，审计失败拒绝高风险执行。路径由Rust规范化并按项目授权，参数数组执行受控程序，只管理自有进程；路径TOCTOU/凭据库/真实原子审批是功能上线前验收。

已将framework_probe迁移v1，生成两个实验app命令的显式权限，只授权本地main；旧0.4字符串接口仍是实验，路径guard加强联接/ADS/穿越检查。22项Rust、4项IPC、15项离线Codex与真实嵌入资源桌面验证通过；四类最低威胁都有断言。契约、错误日志、安全用例和实测见ipc-contract.md、errors-and-logging.md、security-checklist.md、ipc-security-verification.md。阶段一新增服务不能以文档/参考guard代替安全边界实测；负责人为工程/安全/集成负责人，复审在0.7和对应功能上线前。

## ADR-0010：阶段门评审完成但不批准阶段一启动

状态：历史阻塞评审（2026-10-11）；已由同日用户确认的 ADR-0011 替代阶段一阻塞结论。以下为原评审依据，当前阶段门按替代范围通过。

依据：R-013 的 cc-switch 受支持完整外部自动接口未验证，社区 CLI 5.11.0 仅通过部分隔离操作；R-014 的真实共享配置/代理路由对外部任务的影响仍未知。两项都关联现有非官方源自动接入需求，当前没有用户确认的替代验收范围。其他领域按 `phase-gate-review.md` 中的采用/有条件采用/暂缓决定执行，风险 R-005、R-016、R-019、R-020 在对应功能上线前关闭。

在解除阻塞前，允许继续整理估算与不触及共享配置的准备工作；不得固化未验证的 cc-switch 生产契约或宣称自动 AI 配置通过。关闭路线为：证明受支持的外部接口与共享路由隔离，或经产品负责人明确调整 FR-AI-006 并补充替代实现及验收 ADR。官方源依旧仅作预留，不纳入此决策。

## ADR-0011：采用手动 cc-switch / 应用自管 profile
