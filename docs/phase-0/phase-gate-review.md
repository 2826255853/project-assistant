# 步骤 0.7：阶段门评审与阶段一启动清单

日期：2026-10-11（Asia/Shanghai），按用户确认的替代方案复审。评审依据：计划文档 v1.3、[ADR-0011](self-managed-profile-adr.md) 和截至本日的阶段 0 验证记录。

## 评审结论

**步骤 0.3、0.7 及阶段 0 通过（按已确认替代范围），允许启动阶段一。** 此结论基于用户明确选择手动 cc-switch / 应用自管 profile，以及既有通信和独立 home 实验证据，不代表自管产品功能已实现。原阻塞评审保留在 ADR-0010。

cc-switch 自动读取、编辑、切换和凭据管理退出当前需求，R-013 因范围调整关闭。共享全局切换路线不采用；R-014 保留为自管配置功能上线门，须验证环境/项目覆盖拒绝、实际路由隔离及既有任务不受外部配置影响。社区 CLI 部分能力和旧 blocked 报告保持历史结论，不解释成完整自动集成通过。

本轮未进行新的外部集成实验，未读取真实 Key 或修改用户共享配置。采用 [ADR-0011](self-managed-profile-adr.md) 的应用自管方案：用户手动录入 profile/Key，自有进程使用专属配置；生产凭据库、隔离与完整恢复通过前，不开放真实 Key/任务功能。

### 工程结构与完成边界

保留当前 `src/` 与 `src-tauri/` 根结构，按实际功能新增页面/组件与 Rust 服务；`src/ipc/` 保留 DTO 和唯一调用入口，`storage/` 管仓储，迁移仅追加。Rust 适配器仅包含 Codex、自管配置、Git 和 Opener，不创建 cc-switch 自动适配器；模块随对应任务创建。

阶段一最终验收须证明：桌面启动/关闭、设置重启恢复、严格 IPC/固定错误、日志数据库无完整 Key；AI 配置按自管路线验收，cc-switch 未安装/升级不影响已有有效配置。真实凭据与自管隔离/恢复未通过时能力不可用。完整项目管理、Git、搜索、对话与差异仍按阶段二至四推进。

## 本轮核验

当前计划、README、实验/风险/ADR、IPC 和验收摘要已同步替代范围；历史记录与报告保留原当时结论，以 ADR-0011 为当前执行依据。

历史 0.7 回归：`npm run build`、`npm run verify:ipc` 通过，22 项 Rust、4 项 IPC、15 项 Codex 离线与真实 WebView2 的 7 项检查通过；这组证据只证明参考实现。替代范围本轮已通过 `npm run build`、`npm run test:ipc`（4 项）、`npm run test:codex`（15 项）及本地文档链接核验（60 个）；没有新增真实桌面/远端/共享路由实验，不借旧报告宣称生产隔离或凭据库通过。

## 已确认的产品决策

用户已明确选择“用户手动管理 cc-switch、应用自管 profile”，无需再次确认。FR-AI-006 与验收范围已改写，采用 ADR-0011；旧 cc-switch 自动接入仍未实测通过。该决策不要求读取真实 Key、改写用户共享配置或继续社区 CLI 集成研究。官方源预留约定不变。
